# 하네스 업데이트에 따른 단원 점검

이 Skill의 원본은 `education-harness/common/tools/education-haness-review/`에 있습니다.<br>
아래 상대 링크는 `.agents/skills/`의 연결 경로가 아닌 원본 폴더를 기준으로 읽습니다.

## 입력과 점검 범위

- 필수 입력은 단원 범위입니다. 예: `09~10장`, `08-7`, 특정 교재 경로.<br>
  현재 요청이나 대화에서 범위를 알 수 없다면 범위만 묻고, 전체 과정으로 넓히지 않습니다.
- 선택 입력은 비교할 이전 하네스 버전·Git 커밋입니다.<br>
  지정하지 않으면 [출처 기록](../../../SOURCE.md)의 최신 버전에서 변경된 기준을 점검합니다.<br>
  “최신 기준 전체”를 요청하면 해당 단원에 적용되는 현재 기준 전체를 사용합니다.
- 기본은 읽기 전용입니다. 교육 자료·하네스·코드·설정을 바꾸거나 테스트·Live 호출을 실행하지 않습니다.<br>
  결과 파일 저장이나 테스트 실행도 요청받은 경우에만 해당 범위에서 수행합니다.

## 수행 방법

1. [하네스 안내](../../../README.md)에서 검토 작업으로 분류하고 [기존 자료 검토](../../workflows/review-materials.md)를 따릅니다.<br>
   [프로젝트 설정](../../../project.md)의 독자·단원 대응·기술 기준 중 필요한 부분으로 대상 문서와 실습을 찾습니다.
2. `git status`와 [공통 버전](../../VERSION)·출처 기록으로 현재 기준을 확인합니다.<br>
   비교 버전이 있으면 관련 기준 파일의 Git 변경분을 확인하고, 버전명만으로 Git 태그가 있다고 가정하지 않습니다.<br>
   최신 업데이트만 점검할 때도 출처 기록의 요약을 해당 규칙 원문과 대조합니다.<br>
   커밋하지 않은 기준 변경이 있으면 점검에 포함했는지 밝힙니다.<br>
   이전 원문을 찾을 수 없다면 확인 가능한 현재 기준만 점검하고, 정확한 변경분은 확인하지 못했다고 구분합니다.
3. 변경된 기준 중 지정 단원에 관련 있는 항목만 선택합니다.<br>
   지정 범위의 메인 교재·하위 설명·연결된 샘플·테스트를 대조합니다.<br>
   선수 학습과 공통 지원 코드는 설명의 근거 확인에 필요한 부분만 읽고 별도 단원의 개선 목록으로 확대하지 않습니다.
4. 각 문제를 기준 원문과 실제 문서·코드 위치로 뒷받침합니다.<br>
   기존 예제 보존과 개선 필요성은 [검토 기준](../../rules/review.md)으로 판단하고, 문제가 없는 자료에 변경을 강제하지 않습니다.

## 결과: 다음 반영 작업에서 사용할 개선 목록

처음에 대상 단원·기준 버전·비교 범위·읽은 파일·테스트 실행 여부를 요약합니다.<br>
다음 표를 사용하되 같은 원인의 문서·코드 문제는 한 항목으로 묶습니다.

| ID | 중요도 | 대상 위치 | 적용 기준 | 문제와 학습에 미치는 영향 | 제안하는 변경·유지할 동작 |
|---|---|---|---|---|---|
| R01 | 높음/중간/낮음 | 파일·절 또는 클래스·메서드와 확인한 줄 번호 | 기준 파일·절 | 실제 근거를 들어 설명 | 수정 범위와 보존할 예제·입출력 등 |

ID는 이 점검 결과 안에서 고정하고, 다른 결과에도 R01이 있으면 점검 대상과 함께 구분합니다.<br>
문제 없음·추가 확인 필요·검토하지 못한 범위는 수정 항목과 구분합니다.<br>
해당 업데이트가 없거나 단원에 관련이 없으면 그 사실을 알리고 전체 검토로 확대하지 않습니다.

후속 반영은 `$education-haness-apply`에 이 목록과 선택한 ID를 전달합니다.<br>
같은 대화에서는 목록을 그대로 사용하고, 다른 대화에서 사용하려면 요청받은 경로에 결과를 저장합니다.<br>
저장한 결과에도 단원 범위·비교 기준·ID·근거·제안을 포함하고 기존 파일을 임의로 덮어쓰지 않습니다.
