# 점검한 개선 항목 반영

이 Skill의 원본은 `education-harness/common/tools/education-haness-apply/`에 있습니다.<br>
아래 상대 링크는 `.agents/skills/`의 연결 경로가 아닌 원본 폴더를 기준으로 읽습니다.

## 점검 결과와 사용자 선택 확인

- 입력은 `$education-haness-review`가 만든 개선 목록과 반영할 ID입니다.<br>
  같은 대화의 목록 또는 사용자가 지정한 점검 결과 파일을 읽습니다.<br>
  같은 정보가 있는 기존 점검 목록도 사용할 수 있으며 특정 표 형식으로 다시 작성할 필요는 없습니다.
- `R01과 R03`, `높음 항목만`, `목록 전부`처럼 선택한 범위를 확정합니다.<br>
  단순히 “반영해”라고 했고 직전 목록이 하나라면 그 목록의 확정된 개선 항목 전체를 뜻합니다.<br>
  점검 결과가 없거나 여러 목록 중 대상을 정할 수 없으면 결과 위치나 선택 대상을 묻습니다.<br>
  새 점검을 몰래 수행해 반영할 항목을 만들지 않습니다.

## 수행 방법

1. [하네스 안내](../../../README.md)에서 수정 작업으로 분류하고 [기존 자료 수정](../../workflows/update-materials.md)을 따릅니다.<br>
   [프로젝트 설정](../../../project.md)의 필요한 범위·코드 형식·검증·커밋 방식을 확인합니다.
2. `git status`와 선택 항목의 기준 원문·현재 문서·코드를 대조합니다.<br>
   점검 당시 줄 번호보다 현재 내용으로 위치를 찾고, 문제와 개선안이 여전히 유효한지 확인합니다.<br>
   이미 해결된 항목은 다시 수정하지 않습니다.<br>
   사용자 편집이나 기준 변경으로 제안이 맞지 않게 됐다면 해당 항목을 보류하고 이유를 알립니다.<br>
   판단 가능한 다른 선택 항목은 계속 진행합니다.
3. 선택한 개선안의 목적과 보존할 동작에 맞춰 필요한 문서·코드·테스트를 함께 수정합니다.<br>
   범위 밖의 별도 개선이나 규칙 추가는 하지 않습니다.<br>
   지정 범위 밖의 공통 코드 수정이 필요해지면 영향과 대안을 먼저 알리고 그 변경은 범위 확인 뒤 진행합니다.
4. [검증 절차](../../workflows/verify-materials.md)에서 변경에 필요한 검사만 수행합니다.<br>
   코드 변경은 해당 프로젝트의 로컬 검증 대상을 선택하고, 문서만 바꾸면 관련 링크·발췌·설명을 확인합니다.<br>
   이번 요청이나 기존 대화에서 허용하지 않은 실제 외부 API 호출은 실행하지 않습니다.<br>
   검증 실패를 숨기거나 테스트를 삭제해 통과시키지 않습니다.

## 결과

원래 ID를 유지해 다음 내용을 알립니다.

| ID | 처리 상태 | 기존 → 변경 | 변경 파일·검증 결과 또는 보류 이유 |
|---|---|---|---|
| R01 | 반영/이미 해결/보류 | 실제 변경 요약 | 확인한 근거와 미검증 범위 |

선택하지 않은 항목은 수정하지 않았음을 짧게 알립니다.<br>
반영한 내용을 검증한 것과 검증하지 못한 것을 구분하고, 커밋은 사용자 요청과 프로젝트 설정을 따릅니다.<br>
점검 결과 파일은 요청 없이 고쳐 쓰지 않습니다. 원본 결과와 이번 반영 결과를 구분해 전달합니다.
