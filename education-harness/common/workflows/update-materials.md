# 기존 자료 수정

1. 사용자가 지정한 실제 파일과 주변 문맥을 읽습니다. 줄 번호만으로 위치를 단정하지 않습니다.
2. 요청이 문장 수정, 예제 확장, 파일 이동, 설정 통일 중 무엇인지 구분합니다.
3. 기존 편집과 예제를 보존하면서 필요한 범위만 수정합니다. 검토만 요청한 경우는 [검토 절차](review-materials.md)를 사용합니다.

| 변경 종류 | 확인할 범위 |
|---|---|
| 문장·용어 | 사실·문맥·같은 개념의 표현, Markdown 형식 |
| 예제 코드 | 관련 실제 소스·API·컴파일·해당 동작 테스트 |
| 예제 순서 | 선수 개념, 앞·뒤를 가리키는 문장, 본문·보충 링크 |
| 파일·모듈 이동 | 빌드 등록, 명령, 본문·README·상위 안내·앵커와 IDE 동기화 |
| 문서 분리 | 분리된 페이지의 소스 링크, ‘위·아래·앞서’의 대상, 현재 페이지 자료와 확인 질문의 대응 |
| 설정 통일 | 실제 설정, 실행 위치, 테스트의 대체 설정, 문서 코드 블록과 실행 안내 |
| 예상 시간 변경 | 소수업·단원·전체 시간의 기준과 합계, 상위 시간표와 주차 계획 |

4. 관련 링크·코드·명령을 파일 검색으로 찾고 함께 정리합니다. 단순 이름 변경으로 소스 내용을 불필요하게 바꾸지 않습니다.
5. [검증 절차](verify-materials.md)에서 변경과 관계 있는 검사만 실행합니다. 문장 하나 수정에 테스트 코드를 새로 만들지 않습니다.
6. 변경 내용과 확인 범위를 간단히 알립니다. 커밋 여부와 범위는 프로젝트 설정·사용자 지시를 따릅니다.
