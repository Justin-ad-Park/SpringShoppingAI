작성 지침: 필요한 절만 사용하고 중괄호와 이 안내를 결과물에서 제거합니다. 기술·언어·빌드 도구는 프로젝트 설정을 따릅니다.

## 이번 목표와 학습 범위

선수 지식, 예상 시간, 이번에 도입할 주요 개념 하나와 완료 기준을 밝힙니다.
필수 읽기와 선택 보충의 경로를 안내합니다.

## 어떤 문제를 해결할까?

독자가 아는 상황에서 출발해 입력·처리·결과를 설명합니다.
새 용어를 정의하고, 그림이 이해를 돕는 경우에만 추가합니다.

## 코드 읽기

실제 소스 위치와 직접 읽을 메서드를 안내합니다.
전체 파일·발췌·구조 설명용 코드 중 어느 것인지 표시합니다.
새 문법을 짧게 설명하고, 보조 코드가 있다면 역할과 읽을 시점을 구분합니다.
설명에 필요한 객체·필드·보조 메서드가 어디에서 준비되는지 안내하고, 설명하는 동작을 해당 코드에 연결합니다.
객체 생성·요청 구성·실제 실행·결과 읽기가 다른 시점이라면 구분해서 설명합니다.

## 실행과 결과

설정 준비, 작업 디렉터리, 실제 실행 명령을 제공합니다.
입력 예와 기대 결과를 보여주고 실제 기록과 응답 형태 예시를 구분합니다.
외부 서비스 호출 여부와 필요한 설정을 명시합니다.
관찰할 항목의 확인 위치를 응답 필드·로그·테스트 검증문 등으로 지정합니다. 현재 출력으로 확인할 수 없는 값을 비교하라고 요구하지 않습니다.

## 하나 바꿔 보기

질문·입력·옵션 하나를 바꾸고, 무엇이 달라질지 비교합니다.
수정 전 결과 확보 → 하나 변경 → 필요시 재시작·재적재 → 같은 입력으로 비교 → 원복 순서로 안내합니다.
실험 데이터가 실제로 비교할 차이를 만들 수 있는지 확인하고, 변화가 없을 수 있다면 이유를 설명합니다.

## 실패와 한계

주요 실패 한두 개를 재현하고, 코드가 보장하는 것과 보장하지 않는 것을 구분합니다.
상태 이름은 통과한 검사의 범위로 해석합니다. 기존 구현을 대체한다면 저장·변경 시점과 실패 후 상태의 차이도 설명합니다.
긴 내부 처리와 심화 설명은 보충 문서로 연결합니다.

## 테스트는 무엇을 확인할까?

테스트 파일·실행 명령·핵심 검증 내용을 안내합니다.
가짜 응답·실제 구현·실제 외부 모델 중 어떤 범위를 확인하는지 명시합니다.

## 확인 질문

외운 용어보다 입력·처리·결과와 판단·실행 주체를 설명할 수 있는지 확인합니다.
현재 페이지에 제시한 코드·표·그림을 대상으로 질문합니다. 메서드가 없는 페이지에 ‘위 메서드를 다시 읽으라’ 같은 안내를 남기지 않습니다.
해설을 제공하고, 앞 단원·다음 단원·목차로 이동할 실제 링크를 연결합니다.
