# 교육 하네스 행동 평가

교재 테스트는 코드가 동작하는지 확인하고, 이 평가는 에이전트가 요청에 맞게 절차·컨텍스트·수정 범위·검사를 선택하는지 확인합니다.
[평가 사례](cases.md)는 기본·선택 사례와 과정별 사례의 위치를 안내합니다. 전용 실행 엔진·Python 프로그램·추가 에이전트 역할은 필수가 아닙니다.

## 사례 선택과 요청 작성

절차 선택·권한 판단·수정 범위·검사 선택을 바꾸는 지침 변경을 대상으로 관련 사례를 선택합니다. 의미가 바뀌지 않는 표현·링크 수정에는 독립 세션 평가를 요구하지 않습니다. 실행하지 못한 행동은 미검증으로 남깁니다.

- 기본 사례는 변경에 관계있는 항목부터 선택합니다. 설계 관련 변경에는 선택 사례를, 기술·검증 설정 변경에는 프로젝트 설정의 과정별 사례를 추가합니다. 모든 작업에 전체 사례 실행을 요구하지 않습니다.
- 사용자 요청에는 목적·대상·허용 범위를 씁니다. 유지할 동작, 수정·실행 금지 같은 실제 제약은 명시하되 정답 클래스 구조나 삭제할 문장을 미리 지시하지 않습니다.
- 합격 기준에는 요청에 따라 평가할 행동과 보존할 계약을 씁니다. 요청이 검토 전용이면 실제 수정 대신 근거와 개선안으로 평가합니다. 정상 입력에서는 문제가 없다는 판단도 인정합니다.
- 같은 능력의 문제·정상 입력에는 같은 요청을 사용하고 각각 독립 실행합니다. 특정 해법·새 이름보다 결과와 근거를 평가합니다.
- 반복 확인할 위험·행동이 있는 경우에만 새 사례를 추가합니다. 단순 편집 기준은 작성·검토 규칙으로 확인하고, 특정 과정의 명령·경로는 프로젝트 설정으로 분리합니다.

## 준비와 실행

1. 평가할 하네스 버전·커밋을 고정합니다. 사례마다 비밀 설정이 없는 새 임시 작업 폴더를 사용합니다. 원본 저장소에서 평가용 수정 작업을 하지 않습니다.
2. 적용할 AGENTS.md, README, 규칙·절차·템플릿, 기술별 사례에 필요한 프로젝트 설정의 실행 정보만 복사합니다. 프로젝트 설정에 포함된 평가 요청·합격 기준은 평가 대상에게 제공하지 않습니다. `.env`, 키, 개인 설정, 과거 reports/·context/는 복사하지 않습니다. 기술별 경로를 변경하면 입력 버전을 기록합니다.
3. 평가자가 공통 또는 과정별 사례에 지정된 입력 자료를 지정 경로에 복사합니다. 실행 대상 에이전트에는 사용자 요청과 필요한 입력만 제공합니다. 채점 기준·예상 답안이 들어 있는 cases.md와 이전 평가 결과는 제공하지 않습니다.
4. 정상 동작하는 Codex 등 호스트에서 새 세션을 시작해 요청을 실행합니다. 같은 긴 대화에서 여러 사례의 요청을 이어 보내면 앞 사례의 답이 다음 판단에 영향을 주므로 독립 실행과 구분합니다.
5. 결과물·변경 파일·도구 실행 기록·최종 답변을 확보하고 아래 기준으로 판정합니다. 에이전트의 자기보고만으로 어떤 파일을 읽었거나 검사를 실행했다고 확정하지 않습니다.

평가 자료의 의도적인 문제는 에이전트가 찾아야 할 입력입니다. 실제 교재 결함이나 실행 가능한 애플리케이션으로 취급하지 않습니다.
하네스 평가 절차를 평가 대상에게 수행하라고 요청하는 것이 아니라, 평소의 교육 작업 요청을 줘서 올바른 절차 선택을 관찰합니다.

## 판정과 기록

| 관점 | 확인할 증거 |
|---|---|
| 결과 | 요청한 수정·검토 결과, 보존해야 할 코드와 파일 |
| 과정 | 도구 기록에 나타난 읽기·수정·실행 범위, 로컬/Live 선택 |
| 설명 | 근거·미검증 범위를 정확하게 설명했는지 |
| 효율 | 불필요한 새 모듈·전체 테스트·전체 문서 읽기를 강제하지 않았는지 |

각 필수 조건을 통과·실패·미확인으로 기록합니다. 기록이 없어 확인할 수 없는 조건은 미확인, 실행 자체를 못 한 사례는 미실행입니다.
필수 조건이 모두 확인되어 통과한 사례만 사례 통과로 셉니다. 미실행을 실패나 통과로 바꾸지 않으며, 실행한 사례 수와 전체 사례 수를 함께 표시합니다.
부정 사례뿐 아니라 정상 입력과 교육 외 요청도 유지합니다. 규칙이 늘었다는 이유만으로 판정 기준을 넓히지 않습니다.

결과는 프로젝트의 reports/에 다음 정보를 남깁니다. [일반 검증 기록](../workflows/verify-materials.md#6-완료-근거)과 실행 여부를 맞춥니다.

```text
하네스 버전·커밋 / 입력 자료 버전:
호스트·모델·실행 설정(확인 가능한 값만):
사례 ID / 사용자 요청 / 실행 일시:
결과물·변경 내역·도구 기록 위치:
필수 조건별 판정과 근거:
사례 판정 / 실행하지 못한 이유:
선택한 사례 ID와 선택 이유 / 이번에 선택하지 않은 사례:
선택 N개 중 실행 N개 / 통과 N개 / 실패 N개 / 미확인 N개 / 미실행 N개:
```

선택하지 않은 사례와 선택했지만 실행하지 못한 사례를 구분합니다. 버전 비교는 같은 사례 집합·입력·판정 기준을 사용합니다. 모델·호스트가 바뀌었다면 함께 기록하고 하네스만의 효과로 단정하지 않습니다.
링크 검사나 사람이 사례를 읽은 점검은 평가 자료의 정적 검증이며 에이전트 행동 평가가 아닙니다.
