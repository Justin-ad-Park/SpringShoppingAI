# 문서 적재와 검색

## 목표

문서를 미리 저장한 뒤 질문과 관련된 원문을 찾고 결과를 해석합니다.

## 왜 필요한가?

고객이 “운송 요금”이라고 물어도 “기본 배송비 3000원”이라는 정책을 찾아야 합니다. 벡터 검색은 두 표현을 임베딩한 숫자 벡터로 비교합니다.

## 용어

- 벡터 저장소는 문서와 벡터를 보관하고 유사도로 검색합니다.
- query는 찾을 내용이며, 예제에서는 “운송 요금”입니다.
- topK는 반환할 문서 수의 상한입니다. 세 문서만 있으면 topK=5여도 다섯 개를 만들지 않습니다.
- score는 질문과 문서의 유사도입니다. 문서가 사실일 확률은 아닙니다.

## 입력과 처리 순서

이 예제는 시작 시 add(documents)로 정책 문서를 임베딩해 저장합니다. 검색 시 similaritySearch(request)에 질문과 topK를 전달하면 저장소가 질문을 임베딩하고 문서 벡터와 비교해 원문·ID·점수를 반환합니다.

문서와 질문은 같은 모델과 차원 설정으로 임베딩해야 합니다. 배열 길이가 같아도 다른 모델의 벡터를 섞지 않습니다. 모델을 바꾸면 문서도 새 모델로 다시 임베딩합니다.

## 실행 조건과 결과 읽기

저장소는 프로세스 메모리에 있으므로 재시작하면 새로 적재하며 임베딩 API 사용량이 다시 발생합니다. 실제 모델에서는 질문 검색에도 사용량이 발생합니다.

결과 ID가 shipping이면 배송 원문을 찾은 것입니다. 원문에 배송비와 무료배송 조건이 실제로 있는지 읽고 점수만으로 정답이라고 판단하지 않습니다. 여기서는 원문을 반환하며 답변 문장을 생성하는 단계는 다음 수업에서 다룹니다.

## 제작 과정 메모

초안에서는 클래스 이름을 세 번 바꿨고 표의 위치도 여러 번 옮겼습니다. 파일 이름을 정할 때 사용한 임시 후보 목록은 현재 실습과 관계없습니다.

## 이번에 사용하지 않는 옛 API 조사

이 실습에서 사용하지 않는 폐기 예정 클래스들의 배포 폴더와 문서 주소 변경 내역을 따로 조사했습니다. 여기서 다루는 적재·검색 API의 실행에는 영향이 없고 이후 수업에서도 사용하지 않습니다.
