# 다이어그램 기준

설명을 돕는 그림이 필요한 경우에만 사용합니다. 모든 절에 그림을 의무적으로 넣지 않습니다.

| 질문 | 그림 | 표현 기준 |
|---|---|---|
| 시간에 따라 누가 무엇을 호출하는가 | 시퀀스 다이어그램 | 호출자 → 애플리케이션 → 라이브러리·외부 시스템. 위에서 아래로 시간 진행 |
| 다음 행동을 누가 결정하는가 | 플로우차트 | 처리와 판단을 구분하고 판단 주체를 명시 |
| 어떤 객체가 무엇을 사용하는가 | 클래스 다이어그램 | 실제 타입·의존 관계 사용. 인스턴스 이름은 타입과 구분 |

- 문제와 새 용어를 먼저 설명하고 그림 → 핵심 코드 → 실행 결과로 연결합니다.
- 시퀀스의 `->>`는 호출·전달, `-->>`는 반환·응답으로 사용합니다. 비동기 동작 여부는 별도로 설명합니다.
- `loop`·`alt`와 분기는 실제 구현 또는 명시한 가능한 경로에만 사용합니다.
- 저장·변경 작업은 외부 호출 전인지, 정상 응답 후인지 구분합니다. 실패 처리가 학습 주제라면 실패 후에도 남는 상태와 실행되지 않는 작업을 표현합니다.
- 실제 클래스와 단계의 이름을 사용합니다. 다음 단원의 구성 요소를 미리 끌어오지 않습니다.
- 코드가 보장하는 처리와 모델 등이 선택할 수 있는 경로를 구분합니다.
- 보조 코드가 핵심 흐름을 가리지 않게 합니다. 테스트용 대체 서버는 테스트 설명에서 다룹니다.
- 색상만으로 역할이나 중요도를 구분하지 않습니다. 텍스트로도 뜻을 파악할 수 있게 합니다.
- 문법 확인과 실제 렌더링 확인을 구분해서 기록합니다. 문법 통과를 그림의 교육적 적절성 검증으로 간주하지 않습니다.

기술별 통신 경계와 용어는 프로젝트의 다이어그램 안내에서 보완합니다.
