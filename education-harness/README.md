# 교육 자료 제작 하네스

교육 자료의 작성 규칙, 작업 절차, 검토 역할, 템플릿과 기존 검증 도구의 사용 방법을 묶습니다.
기본 작성은 한 에이전트로 진행할 수 있고, 검토 역할을 분리해 품질을 확인합니다.
별도 실행 엔진·Python 검사 프로그램·전역 플러그인은 필요하지 않습니다.
지침을 읽는 것으로 완료하지 않고, 실제 파일 확인과 테스트·빌드 결과를 남깁니다.
`AGENTS.md`를 자동으로 읽는 도구에서는 저장소 진입 규칙으로 사용합니다. 다른 도구에서는 이 README와 프로젝트 설정을 작업 시작 시 직접 지정합니다.

## 현재 프로젝트에서 시작하기

1. [프로젝트 설정](project.md)에서 이번 과정과 검증 범위를 확인합니다.
2. [작성 원칙](common/rules/authoring.md)을 읽습니다. 그림이 필요하면 [다이어그램 기준](common/rules/diagrams.md)도 읽습니다.
3. 아래 표에서 요청에 해당하는 절차 하나를 선택합니다.
4. [검토 기준](common/rules/review.md)과 [검증 절차](common/workflows/verify-materials.md)를 변경 범위에 맞게 적용합니다.

| 요청 | 사용할 절차 | 기본 산출물 |
|---|---|---|
| 새 과정의 구성안 | [과정 계획](common/workflows/plan-course.md) | 대상·목표·선수 지식·단원 순서와 완료 기준 |
| 새 단원의 구현 | [단원 작성](common/workflows/write-lesson.md) | 실행 코드·테스트·문서·검증 결과 |
| 기존 문장·예제·파일 위치 수정 | [기존 자료 수정](common/workflows/update-materials.md) | 요청 범위의 변경과 관련 링크·명령 정리 |
| 강사 관점의 검토 | [교육 자료 검토](common/workflows/review-materials.md) | 위치·문제·이유·개선안·중요도 |

요청 예:

> education-harness의 프로젝트 설정과 단원 작성 절차를 적용해서 MCP 입문 단원의 구성안을 먼저 제시해줘.

> education-harness의 검토 절차로 02장과 보충 문서를 검토해줘. 수정하지 말고 중요도별 개선점을 알려줘.

## 역할과 실행 방식

| 역할 | 책임 | 넘겨줄 결과 |
|---|---|---|
| 진행 담당 | 요청 범위·학습 순서·검증 범위 관리, 의견 반영 확인 | 작업 범위와 완료·미완료 목록 |
| 작성자 | 설명·실행 코드·테스트 구현 | 변경 파일과 실행 방법 |
| 교육 검토자 | 초급자의 선수 지식, 설명 순서, 예제와 문장의 적절성 확인 | 근거가 있는 개선 항목 |
| 기술 검토자 | 버전·API·설정·코드·검증 근거 대조 | 불일치와 검증의 한계 |

작은 수정은 단일 에이전트가 작성 후 관점을 바꾸어 순차 검토합니다.
새 단원이나 큰 개편에서는 별도 검토 에이전트를 사용할 수 있지만, 사용자 요청과 실행 환경의 위임 규칙을 따릅니다.
별도 에이전트를 실행하지 않았다면 독립 검토를 받았다고 기록하지 않습니다.
위임할 때는 목표·변경 범위·대상 독자·검토 기준·기대 결과를 전달하고, 읽기 전용 검토자는 파일을 수정하지 않도록 합니다.

## 다른 프로젝트에서 재사용하기

1. 이 폴더를 대상 저장소 안에 복사합니다. `.git`이나 실제 API 키는 복사하지 않습니다.
2. `common/`은 공통 원본으로 유지하고, [프로젝트 설정 템플릿](common/templates/project.md)으로 `project.md`를 교체합니다.
3. 대상 저장소의 `AGENTS.md`에 아래 안내를 병합합니다. 기존 파일 전체를 덮어쓰지 않습니다.

```text
교육 자료 작업일 때 education-harness/README.md와 education-harness/project.md를 읽고
해당 작업 절차를 적용한다. 일반 기능 개발에는 교육 형식을 강제하지 않는다.
```

4. 문서·코드 경로와 검증 명령을 대상 프로젝트에 맞게 확인합니다. Spring·Gradle·.env 사용을 공통 필수 조건으로 가져가지 않습니다.
5. [출처 기록](SOURCE.md)에 가져온 공통 버전과 프로젝트별 보완 내용을 남깁니다.

현재는 이 저장소에서 첫 적용 중입니다. 다른 교육 주제에 실제 적용해 재사용성을 확인한 뒤 별도 Git 저장소로 추출합니다.
별도 저장소를 만들거나 다른 프로젝트에 자동 배포하는 단계는 아직 수행하지 않습니다.
공통 원칙을 개선할 때는 `common/`의 버전과 변경 기록을 갱신하고, 개별 과정의 예외는 `project.md`에 둡니다.

## 검증과 한계

파일 검색·비교, Markdown 링크 확인, Mermaid 미리보기·파서, 프로젝트의 테스트·빌드 도구를 사용합니다.
검사 방법과 결과를 재현할 수 있게 [검증 절차](common/workflows/verify-materials.md)에 기록 기준을 정했습니다.
사용 가능한 도구가 없으면 그 검사를 미실행으로 남기며, 에이전트의 눈대중을 파서 통과로 기록하지 않습니다.
전용 자동 검사기나 CI가 설치된 구성은 아닙니다. 필요가 확인되면 반복 검사의 일부만 추가합니다.

학습자 문서에는 수업 내용과 실행 방법을 남기고, 제작 과정과 검토 기록은 이 하네스 폴더에서 관리합니다.

초기 적용에서 무엇을 확인했는지는 [적용·검토 기록](reports/2026-11-03-initial-application.md)에 정리했습니다.
