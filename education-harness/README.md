# 교육 자료 제작 하네스

이 폴더는 교육 작업의 지침·절차·템플릿을 제공합니다. 실제 에이전트 실행, 도구 호출, 작업 공간 권한은 Codex 등 호스트 실행 환경이 담당합니다.
기본은 한 에이전트가 작성 후 관점을 바꾸어 검토하는 방식입니다. 별도 실행 엔진·전역 플러그인·필수 Python 프로그램은 없습니다.

## 요청부터 분류하기

먼저 아래 표에서 작업을 고른 뒤 필요한 자료만 읽습니다. 여러 유형이 섞이면 관련 행을 함께 적용하고, 이미 읽은 공통 지침은 변경되거나 불확실할 때만 다시 읽습니다.
일반 서비스 기능 개발에는 교육 템플릿을 강제하지 않습니다. 다른 도구에서는 이 README를 진입점으로 직접 지정합니다.

| 요청 | 읽을 절차·기준 | 프로젝트 설정에서 필요한 절 | 산출물 |
|---|---|---|---|
| 새 과정의 안·계획 | [과정 계획](common/workflows/plan-course.md), [작성 규칙](common/rules/authoring.md)의 설명 수준 | 대상·기준 문서·기술 | 계획안. 구현 요청 전에는 코드 생성 안 함 |
| 기존 자료 검토만 | [검토 절차](common/workflows/review-materials.md), [검토 기준](common/rules/review.md) | 대상·기준 문서, 관련 동작·검증 정보 | 위치·근거·개선안. 파일 수정 안 함 |
| 문장·링크 등 작은 수정 | [수정 절차](common/workflows/update-materials.md), 관련 작성 규칙 | 대상·해당 문서·커밋 방식 | 요청한 수정과 관련 검사 |
| 새 단원·실행 코드 구현 | [단원 작성](common/workflows/write-lesson.md), [작성 규칙](common/rules/authoring.md), [검토 기준](common/rules/review.md) | 대상·기술·관련 모듈·코드 형식·검증·커밋 방식 | 실행 코드·설명·테스트·검증 기록 |
| 하네스 규칙·절차 수정 | [수정 절차](common/workflows/update-materials.md), [행동 평가](common/evals/README.md) | 관련 정책·도구·커밋 방식 | 지침 변경과 정적·행동 검증의 구분 |
| 하네스 자체 평가 | [행동 평가](common/evals/README.md) | 범위·검증·외부 호출 여부 | 사례별 실행 근거와 판정 |

[프로젝트 설정](project.md)은 필요한 절을 찾아 읽는 목록입니다. 그림을 바꿀 때만 [그림 기준](common/rules/diagrams.md)을 추가로 읽습니다.
검사는 [검증 절차](common/workflows/verify-materials.md) 중 변경에 해당하는 절을 적용합니다. 템플릿은 새 문서 작성이나 구조 변경 시에만 사용합니다.

## 파일별 기준 위치

| 알고 싶은 것 | 기준 위치 | 다른 파일에서의 사용 |
|---|---|---|
| 적용 범위와 진입 | 저장소 AGENTS.md와 이 README | 작업 분류와 필요한 자료로 연결 |
| 교육 원칙 | [작성 규칙](common/rules/authoring.md), 그림은 [그림 기준](common/rules/diagrams.md) | 템플릿은 작성 칸, 검토 기준은 질문으로 표현. 상세 원칙 재복사 지양 |
| 변수·메서드·타입·패키지 이름 | [이름 기준](common/rules/naming.md) | 작성·검토·절차·템플릿은 이 문서 참조. 과정별 배치는 프로젝트 설정 |
| 검토 질문·중요도 | [검토 기준](common/rules/review.md) | 절차는 해당 기준을 참조 |
| 작업 순서·검사 방법 | common/workflows/ | 규칙의 설명을 반복하기보다 수행 단계 제시 |
| 독자·기술·검증 명령·과정별 예외 | [프로젝트 설정](project.md) | 실제 빌드·소스에서 사실을 확인하고 관련 안내 갱신 |
| 단원과 실습의 대응 | 프로젝트 설정이 지정한 교육 계획 | 테스트 클래스·로컬 명령은 프로젝트 설정이 관리 |
| 현재 작업과 완료 근거 | 장기 작업은 context/, 큰 변화의 완료 근거는 프로젝트 지정 위치 | 작은 수정은 별도 기록 없이 결과만 안내 |

버전은 실제 선언 파일이 기준입니다. 안내 문서에 같은 값이 필요하면 기준 링크와 함께 유지하고, 원본 변경 시 참조 문서도 검색합니다.
기준 변경은 원칙의 소유 파일부터 고치고 템플릿·검토 질문이 여전히 같은 뜻인지 확인합니다.

## 역할과 실행 방식

아래는 작업 역할이며 에이전트 인스턴스 네 개를 뜻하지 않습니다.

| 역할 | 필수 입력 | 수정 권한 | 완료 조건 |
|---|---|---|---|
| 진행 담당 | 사용자 요청·현재 범위·프로젝트 설정 | 계획·상태 기록 | 범위·남은 작업·검증 한계 정리 |
| 작성자 | 합의된 범위·관련 소스·적용 규칙 | 요청 범위의 문서·코드·테스트 | 실행 가능한 결과와 관련 검증 근거 제공 |
| 교육 검토자 | 대상 독자·순서·검토 대상·관련 코드 | 검토 중 읽기 전용 | 학습 흐름의 문제를 위치·이유와 함께 보고하거나 문제 없음 명시 |
| 기술 검토자 | 실제 버전·코드·설정·실행 결과 | 검토 중 읽기 전용 | 주장과 구현 대조, 검증·미검증 범위 구분 |

짧거나 의존적인 단계는 한 에이전트가 순차 처리합니다. 큰 작업의 독립된 검토만 별도 에이전트를 고려하며 사용자 요청과 실행 환경의 위임 규칙을 따릅니다.
위임할 때는 위 입력·수정 권한·완료 조건을 전달하고, 같은 파일을 동시에 수정하지 않습니다. 별도 에이전트가 없었다면 독립 검토라고 기록하지 않습니다.

## 긴 작업을 이어가기

여러 단원이나 여러 세션에 걸친 작업만 [작업 재개 절차](common/workflows/resume-task.md)와 [상태 템플릿](common/templates/task-context.md)을 사용합니다.
작은 수정마다 상태 파일을 만들지 않습니다. 현재 상태는 context/, 과거 검토·완료 근거는 reports/로 구분합니다.

## 다른 프로젝트에서 재사용하기

1. 이 폴더를 대상 저장소 안에 복사합니다. 실제 키·개인 설정·현재 과정의 context/와 reports/ 기록은 새 프로젝트의 진행 상태로 가져오지 않습니다.
2. common/을 유지하고 [프로젝트 설정 템플릿](common/templates/project.md)으로 project.md를 교체합니다. 프로젝트별 도구 안내도 대상 환경에 맞춥니다.
3. 대상 저장소의 AGENTS.md에 ‘교육 작업이면 이 README에서 작업을 분류하고 해당 절차만 적용한다’는 안내를 병합합니다. 기존 파일을 덮어쓰지 않습니다.
4. Spring·Gradle·.env·커밋 언어를 공통 필수 조건으로 가져가지 않습니다. [출처 기록](SOURCE.md)에 가져온 버전·커밋·적용일을 남깁니다.
5. [행동 평가](common/evals/README.md)의 적용 가능한 사례를 새 프로젝트에서도 확인합니다. 사례의 기술별 경로·명령은 새 설정에 맞춥니다.

현재는 첫 과정에서 적용 중입니다. 재사용성을 확인한 뒤 별도 저장소 추출을 검토하며, 자동 배포나 전역 스킬 설치는 하지 않습니다.

## 검증과 기록

교재 품질·실행 검증과 하네스 행동 평가는 별개입니다. 실제 결과와 도구의 한계를 기록하며, 링크 검사 통과를 에이전트 행동 평가 통과로 표현하지 않습니다.
이 프로젝트의 검사 도구·준비·명령은 [도구 안내](verification-tools.md)에 있습니다. 사용할 수 없는 검사는 미실행으로 남깁니다.
공통 변경은 common/VERSION과 [출처 기록](SOURCE.md)을 함께 갱신하고, 과정별 예외는 project.md에 둡니다.
