## 반복된 모호성의 원인

작성 기준에는 이름이 역할을 드러내야 한다는 일반 원칙이 있었지만, `clients` 같은 숫자 카운터와 `maxModels` 같은 제한 필드를 실제 갱신·비교 코드까지 따라가 점검하는 단계가 없었습니다. 검토 질문도 이름의 역할·대상을 묻는 수준이었습니다. E09는 `handle`·`resolve`처럼 메서드 이름을 다루고 있어 필드의 값 종류, 측정 시점, 상한 단위는 입력과 합격 기준에 포함하지 않았습니다.

따라서 규칙이 존재하는 것과 이 문제 유형을 평가할 수 있는 것은 달랐습니다. 2026-11-05 하네스 보고서는 독립 세션 행동 평가 11개 중 0개를 실행했다고 기록합니다. 기존 명명 기준이 이 유형을 에이전트에게서 막는지 확인한 근거도 없었습니다. 규칙을 더 추상적으로 강조하기보다 관찰 가능한 검사 항목과 평가 입력을 추가했습니다.

## 변경 내용

- `RunState`의 카운터를 `clientCreations`, `modelRequestAttempts`, `toolExecutions`로 구분했습니다. 모델 요청 상한은 `maxModelRequestAttempts`, 나노초 마감 시각은 `deadlineNanos`로 이름을 맞췄습니다. 메서드명도 생성 기록, 모델 요청 시작, 도구 실행 시작을 구분합니다.
- 응답 trace와 테스트·문서의 카운터 이름도 함께 바꿨습니다. 모델 요청 횟수는 `ChatModel.call()` 시작 시도 수이고 SDK 내부 HTTP 재시도는 포함하지 않는다는 범위를 설명했습니다.
- 공통 작성 규칙·검토 질문·검증 절차에 숫자 필드의 대상, 측정 시점, 단위, 범위를 선언부터 읽기 지점까지 대조하도록 추가했습니다. E12는 객체 수와 호출 수, 상한 대상, 시간 단위를 구분하는 입력입니다.
