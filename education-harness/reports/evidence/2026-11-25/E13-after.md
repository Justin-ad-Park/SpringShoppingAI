# 문서 적재와 검색

## 목표

문서를 미리 저장하고, 질문과 관련된 원문을 찾는 과정을 설명할 수 있습니다.<br>
검색 결과에서 원문과 점수를 보고 무엇을 확인해야 하는지 알 수 있습니다.

## 왜 필요한가?

고객이 “운송 요금”이라고 물으면 “기본 배송비 3000원”이라는 정책을 찾아야 합니다.<br>
표현이 달라도 뜻이 비슷한 문서를 찾을 때 벡터 검색을 사용합니다.

이 문서는 적재와 검색의 흐름을 이해하는 개념 자료입니다.

## 용어

- **임베딩**은 문장의 의미를 숫자 목록인 **벡터**로 바꾸는 과정입니다.
- **벡터 저장소**는 문서와 벡터를 보관하고, 질문과 의미가 비슷한 문서를 찾는 데 사용합니다.
- **query**는 검색할 질문입니다.<br>
  예제에서는 “운송 요금”입니다.
- **topK**는 반환할 문서 수의 상한입니다.<br>
  문서가 세 개뿐이면 `topK=5`여도 다섯 개를 채워 반환하지 않습니다.
- **score**는 질문과 문서가 얼마나 비슷한지 나타내는 점수입니다.<br>
  문서 내용이 사실일 확률은 아닙니다.

## 입력과 처리 순서

문서를 저장하는 단계를 **적재**라고 합니다.<br>
이 예제는 다음 순서로 문서를 적재하고 검색합니다.

1. 시작할 때 `add(documents)`로 정책 문서를 임베딩해 저장합니다.
2. 검색할 때 `similaritySearch(request)`에 질문과 `topK`를 전달합니다.
3. 저장소는 질문을 임베딩하고, 저장된 문서 벡터와 비교합니다.
4. 검색 결과로 문서 원문, 문서를 구분하는 ID, 유사도 점수를 받습니다.

문서와 질문은 같은 임베딩 모델과 차원 설정을 사용해야 합니다.<br>
차원은 벡터에 들어 있는 숫자의 개수입니다.<br>
숫자의 개수가 같아도 모델이 다르면 벡터를 섞어 비교하지 않습니다.<br>
모델을 바꾸면 저장할 문서도 새 모델로 다시 임베딩합니다.

## 실행 조건과 결과 읽기

이 예제의 저장소는 실행 중인 프로그램의 메모리에 있습니다.<br>
프로그램을 종료하면 저장한 내용이 사라지므로 재시작할 때 문서를 다시 적재합니다.<br>
실제 임베딩 API를 사용하면 문서를 적재할 때마다 API 사용량이 발생하며, 검색할 질문을 임베딩할 때도 사용량이 발생합니다.

검색 결과의 ID가 `shipping`이면 배송 정책 원문을 찾은 것입니다.<br>
원문을 읽고 배송비와 무료배송 조건이 실제로 있는지 확인합니다.<br>
유사도 점수만으로 질문에 맞는 정답이라고 판단하지 않습니다.

여기서는 검색한 원문을 반환합니다.<br>
원문을 바탕으로 답변 문장을 생성하는 단계는 다음 수업에서 다룹니다.
