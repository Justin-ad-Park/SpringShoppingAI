# 문서 적재와 검색

## 목표

문서를 저장하고, 질문과 관련된 원문을 찾는 과정과 검색 결과를 읽는 방법을 이해합니다.

## 왜 필요한가?

고객이 “운송 요금”이라고 물으면 “기본 배송비 3000원”이라는 정책을 찾아야 합니다.<br>
단어가 달라도 의미가 비슷한 문서를 찾기 위해 벡터 검색을 사용합니다.

## 용어

- **임베딩**: 글의 의미를 숫자 배열인 **벡터**로 바꾸는 작업입니다.
- **벡터 저장소**: 문서와 벡터를 보관하고, 질문과 의미가 비슷한 문서를 찾는 곳입니다.
- **`query`**: 검색할 질문으로, 이 예제에서는 “운송 요금”입니다.
- **`topK`**: 검색 결과로 받을 문서 수의 최댓값입니다.<br>
  저장된 문서가 3개라면 `topK=5`로 설정해도 최대 3개만 받습니다.
- **`score`**: 질문과 문서가 얼마나 유사한지 나타내는 점수입니다.<br>
  문서 내용이 사실일 확률을 뜻하지는 않습니다.

## 입력과 처리 순서

이 예제는 다음 순서로 문서를 저장하고 검색합니다.

1. **문서 저장**: 프로그램이 시작되면 `add(documents)`로 정책 문서를 임베딩해 저장합니다.
2. **질문 검색**: `similaritySearch(request)`에 질문과 `topK`를 전달합니다.<br>
   저장소는 질문도 임베딩한 뒤, 저장된 문서 벡터와 비교합니다.
3. **결과 반환**: 유사한 문서의 원문, 문서를 구분하는 ID, 점수를 받습니다.

문서와 질문은 같은 임베딩 모델과 차원(벡터의 숫자 개수) 설정을 사용해야 합니다.<br>
숫자 개수가 같아도 서로 다른 모델의 벡터를 섞어 비교할 수는 없습니다.<br>
모델을 바꾸면 저장할 문서도 새 모델로 다시 임베딩합니다.

## 실행 조건과 결과 읽기

이 예제는 문서를 프로그램 메모리에 저장하므로, 재시작하면 문서를 다시 임베딩해 저장합니다.<br>
실제 모델을 사용할 때는 이 재저장과 질문 검색 모두 임베딩 API 사용량이 발생합니다.

결과 ID가 `shipping`이면 배송 정책 원문을 찾은 것입니다.<br>
원문을 읽고 배송비와 무료배송 조건을 확인하세요.<br>
점수가 높아도 원문이 질문에 답할 수 있는지 확인해야 합니다.
