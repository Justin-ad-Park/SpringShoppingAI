# Fluent 코드 표현 기준 적용 — 2026-11-05

공통 버전 `0.2.7`에 호출 단계별 줄바꿈과 단순 AssertJ 검증의 한 줄 예외를 반영했습니다.
기준의 소유자는 common/rules/authoring.md이며 검토 질문·검증 절차에서 확인하도록 연결했습니다.
언어와 프로젝트 관례를 따르되 현재 Java 과정의 실행 코드와 문서 예제에는 같은 표현 기준을 적용합니다.

- Fluent 호출은 receiver 또는 정적 생성 호출 뒤부터 한 단계씩 읽도록 줄바꿈합니다. 중첩 인자와 람다 블록의 들여쓰기도 확인합니다.
- 단순 assertThat 검증은 대상의 짧은 접근 체인까지 한 줄로 둡니다. 복합 람다 본문은 블록을 유지합니다.
- 현재 과정은 채팅·임베딩 대역을 분리했지만 이 구현을 공통 하네스의 필수 구조로 만들지 않았습니다. 응답·벡터·분기는 단원에 남겼습니다.
- 별도 평가 사례를 추가하지 않았습니다. 코드·문서 표현은 정적 검토로 확인하고 하네스의 독립 세션 행동 평가는 실행하지 않았습니다.
- 최종 검사: 하네스 링크·앵커 131개, 교재와 공통 도구 안내 403개에서 오류 0개입니다. Mermaid 27개 문법과 공백 검사도 통과했습니다. Java 117개 파일의 표시 형식 변경 전후 주석 외 토큰·문자열을 대조했습니다.
- 코드 검증: 공통 도구 11개와 실습 로컬 71개, 총 82개 통과(실패·오류·건너뜀 모두 0개). 14개 실습 빌드와 실행 JAR의 공통 도구 제외를 확인했습니다. 실제 외부 모델 호출·Live 실행은 수행하지 않았습니다. Mermaid 화면 렌더링과 실제 학습자 이해도는 검증하지 않았습니다.
