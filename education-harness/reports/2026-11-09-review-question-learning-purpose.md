# 확인 질문의 학습 목적 재검토 — 2026-11-09

## 범위와 판단 기준

`Spring-AI-Agent-Learning/docs/lessons`의 Markdown 62개 중 확인 질문이 있는 47개 문서의 질문과 해설을 검토했습니다. 질문이 없는 안내·목차에 새 질문을 요구하지 않았습니다. 해당 수업의 목표·본문과 질문을 대조한 정적 검토이며 별도 에이전트의 독립 검토는 아닙니다.

판단 기준은 “이 샘플의 메서드명·변수명·업무 상태명을 바꿔도 배운 원리를 설명할 수 있는가”입니다. 구체적인 Spring AI API·설정·응답 메타데이터를 묻는 것은 사용법 학습에 필요하므로 유지합니다. 샘플 코드는 판단의 근거로 활용하되 이름이나 위치만 답하게 하지 않습니다. Java 검증·테스트·도메인 책임도 그 수업의 명시한 목표에 필요하면 적절합니다.

## 이번에 수정한 질문

[05 보충 5 도구 호출 제한](../../Spring-AI-Agent-Learning/docs/lessons/05-tool-calling/05-tool-call-limits.md)의 2번을 다음과 같이 수정했습니다.

> 도구 호출 상한 초과 여부를 확인하려면, 왜 `.content()`로 답변 문자열만 읽지 않고 `.chatResponse()`로 응답을 받아야 하나요?

해설은 Spring AI가 응답 메타데이터의 종료 사유 `toolCallLimitExceeded`로 상한 초과를 알리고, `getResult().getMetadata().getFinishReason()`으로 이를 확인한다는 내용입니다. 샘플의 `Reply.status`, `TOOL_LIMIT`, `COMPLETED`는 정답의 대상으로 삼지 않았습니다. 기존의 접힌 통합 해설과 1·2·3번 대응은 유지했습니다.

## 최초 검토의 하네스 보완안 — 후속 적용 완료

기존 [목표와 설명 배치 규칙](../common/rules/authoring.md#목표에-맞는-설명과-배치)은 이미 제목·목표·예제·확인 질문을 같은 개념에 맞추고 코드 위치·이름 나열로 목표를 대신하지 않도록 안내합니다. 새 규칙을 중복해서 늘리기보다 확인 질문 기준에 다음 내용을 구체화하는 편이 좋습니다.

1. **질문의 학습 대상:** 확인 질문은 수업에서 배운 작동 원리·판단 근거·사용법·결과 해석을 확인한다. 샘플 고유의 클래스명·메서드명·상태 문자열·코드 위치를 찾거나 외우는 것만으로 답이 끝나는 질문은 피한다. 구체적인 코드는 추론의 근거로 사용할 수 있다.
2. **기능과 샘플 정책 구분:** 프레임워크 API·설정·메타데이터와 샘플이 정한 업무 정책·응답 형식을 구분한다. 샘플 정책을 묻는다면 그 이름 자체보다 정책을 둔 이유와 변경 시 결과를 묻는다.
3. **수업 종류에 따른 예외:** 실습 준비·Java 문법·테스트 읽기가 명시한 목표인 보충은 그 목표를 질문해도 된다. 모든 확인 질문을 특정 프레임워크 API 암기로 통일하지 않는다.

검토 기준에는 “샘플의 이름을 바꾸어도 배운 원리를 설명하는 질문인가? 코드 위치만 찾으면 끝나지는 않는가?”를 추가할 수 있습니다. 템플릿에는 별도 형식이나 필수 문항을 늘리지 않고 질문 작성 안내에 이 기준의 링크·한 문장을 추가하는 정도면 충분합니다. 기존의 ‘대상 이름·값을 명확히 보여주기’는 유지하되, 대상의 명확성이 학습 목적의 적절성까지 보장하지 않는다는 점을 구분해야 합니다.
