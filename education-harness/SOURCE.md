## 0.2.7 — 2026-11-05

- Fluent API는 단계별 줄바꿈, 단순 assertThat 검증은 한 줄, 복합 람다 검증은 블록 유지로 작성 기준을 구체화했습니다.
- 코드·문서 예제의 표현과 표시 형식 변경 시 호출·인자·문자열 보존을 검토·검증 절차에 연결했습니다. 별도 행동 평가 사례는 추가하지 않았습니다.
- 현재 과정의 채팅·임베딩 대역 분리는 project.md에 기록하고 공통 규칙에는 특정 구현을 강제하지 않습니다.
- 검증 범위와 한계는 [적용 기록](reports/2026-11-05-fluent-code-layout.md)에 남깁니다.

## 0.2.6 — 2026-11-05

- 기본·선택·과정별 평가를 구분하고 변경에 관련된 사례만 선택하도록 정리했습니다. E05는 project.md로 이동하고 E11과 연결 입력은 제거했습니다. JSON 작성·검토 기준은 유지합니다.
- 문제·정상 입력 쌍의 요청을 통일하고 검토 전용 요청은 근거·개선안으로 채점하도록 맞췄습니다. 특정 설계 해법을 유도하던 요청·입력 문장을 정리했습니다.
- 요청에는 목적·대상·권한을, 합격 기준에는 평가 행동을 작성합니다. 과정별 평가 기준도 실행 대상에게 노출하지 않도록 준비 절차를 보완했습니다.
- 적용·검증 범위는 [평가 사례 정리 기록](reports/2026-11-05-evaluation-case-cleanup.md)에 남깁니다. 과거 버전의 사례와 검증 결과는 당시 기록으로 보존합니다.

## 0.1.1 — 2026-11-04

- 설명의 코드 근거, 생성·구성·실행 시점 구분, 구현 대체 시 저장·실패 정책 비교, 상태가 보장하는 범위를 작성·검토 기준에 추가했습니다.

## 0.1.0

- 단계별 개념 확장, 실행 코드와 테스트, 쉬운 한국어, 보충 문서 분리 기준을 정리했습니다.
- 작성·수정·교육 검토·기술 검증의 작업 절차와 결과 형식을 추가했습니다.
- 기존 도구를 직접 사용하는 방식으로 구성했고, 필수 Python 검사 프로그램은 추가하지 않았습니다.
- 기술별 버전·설정·테스트 명령은 공통 규칙에서 분리해 `project.md`에 둡니다.
- 다른 프로젝트에 실제 적용한 검증은 아직 수행하지 않았습니다.

다른 저장소로 복사할 때 원본 저장소·태그 또는 커밋·공통 버전·적용일을 기록합니다.
현재 파일에 존재하지 않는 공개 저장소 주소나 릴리스 태그를 만들어 적지 않습니다.
