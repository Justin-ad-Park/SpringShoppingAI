처음부터 58개 실습을 모두 읽을 필요는 없습니다. 아래 다섯 수업을 같은 쇼핑 상황으로 이어서 실행하세요.
웹 왼쪽의 “처음이라면 이 순서로 시작하세요”에서도 선택할 수 있습니다.

각 수업에서 다음 순서를 반복합니다.

1. **코드:** 화면의 짧은 메소드부터 읽습니다. 실제 Java 파일에서 읽어 오는 코드입니다.
2. **설명:** 질문이 어디로 들어가고 어느 줄에서 AI를 호출하는지 확인합니다.
3. **실행:** 질문 버튼으로 입력칸을 채우고 실행합니다. 버튼만 누른다고 AI를 호출하지 않습니다.
4. **변경:** 숫자·질문·대화 이름 중 하나만 바꾸고 결과를 예상합니다.
5. **테스트:** 준비 → 실행 → 확인 순서의 테스트를 읽고 예상과 비교합니다.

## 가장 짧은 테스트부터 실행하기

```bash
./Spring-AI-Tutor/scripts/test_beginner.sh
```

API 키와 실행 중인 서버가 필요 없습니다. 다음 세 파일의 테스트만 실행합니다.

- [SetupLessonTest](../src/test/java/com/example/shopping/tutor/lesson/l00setup/SetupLessonTest.java): 질문을 보내고 답변 받기.
- [ProductSearchToolsTest](../src/test/java/com/example/shopping/tutor/lesson/l06tools/ProductSearchToolsTest.java): 만원과 만오천원의 검색 결과 비교.
- [ConversationMemoryLessonTest](../src/test/java/com/example/shopping/tutor/lesson/l04memory/ConversationMemoryLessonTest.java): 같은 대화 이름과 다른 이름 비교.

window·DB·조건 병합·웹 연결은 별도 테스트 파일로 나눴습니다. 먼저 위 세 파일을 읽은 다음에 이어서 보세요.

## 그대로 바꿔 볼 과제

- 첫 호출: 질문을 “음료를 추천해줘”에서 “선물할 음료를 추천해줘”로 바꿉니다.
- 상품 검색: 첫 테스트의 가격 10000을 15000으로 바꿉니다. 기존 확인문이 실패하는 이유를 설명하고 P005를 기대 결과에 추가합니다.
- 앞 대화 기억: 두 번째 호출의 대화 이름을 다르게 바꿉니다. 이전 예산이 더 이상 전달되지 않는지 확인합니다.

코드를 바꾼 뒤 웹에서도 확인하려면 실행 중인 Tutor를 종료하고 다시 빌드해서 실행하세요.
`--skip-build`로 실행하면 소스 변경이 반영되지 않을 수 있습니다.

## STUB과 LIVE는 이렇게 구분하세요

- **STUB:** 준비한 응답으로 호출 과정과 Java 검색을 연습합니다. 자유로운 질문을 이해하는 AI가 아닙니다.
- **LIVE:** 실제 API를 호출합니다. 질문에 맞춘 답변과 도구 선택을 확인하며 사용량이 발생합니다.
- 특히 상품 검색의 STUB 인자는 음료·15000원으로 고정돼 있습니다. 가격 변경은 Java 테스트에서 먼저 확인하세요.
- 대화 기억의 STUB은 예산을 말로 답하지 않습니다. 오른쪽에서 실제로 함께 보낸 대화를 확인하세요.
