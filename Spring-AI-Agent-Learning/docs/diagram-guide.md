# 다이어그램을 읽는 공통 기준

00~03의 용어를 익힌 뒤 각 단원의 본문과 함께 참고합니다. 그림은 코드 읽기를 돕는 지도이며 추가 프레임워크가 아닙니다.

| 알고 싶은 것 | 사용하는 그림 | 읽는 방법 |
|---|---|---|
| 누가 무엇을 가지고 호출하는가 | 클래스 다이어그램 | 실제 클래스/record 이름을 사용. 실선 화살표는 사용 관계, 상속은 코드에 있을 때만 표시 |
| 한 요청에서 어떤 순서로 통신하는가 | 시퀀스 다이어그램 | 왼쪽부터 사용자 → 애플리케이션 → Spring AI → 모델. 아래로 갈수록 시간이 지남 |
| 다음 행동을 누가 결정하는가 | 플로우차트 | 사각형은 처리, 마름모는 판단. Java/모델 중 판단 주체를 반드시 글자로 표시 |

- 본문에서 문제·새 용어를 먼저 설명하고, 그림 → 핵심 코드 → 실행 결과 순서로 연결합니다.
- 시퀀스 그림의 `->>`는 호출/전달, `-->>`는 반환/응답입니다. 화살표만으로 비동기 동작을 뜻하지 않습니다.
- `loop`는 반복, `alt`는 조건별 분기입니다. 실제 코드의 반복·분기에만 사용합니다.
- 모델은 문장이나 도구 호출 요청을 반환합니다. 모델에서 Java 메서드로 직접 실행 화살표를 그리지 않습니다.
- 단일 모델 요청과 ChatClient 최상위 요청을 구분합니다. 도구 루프의 반복 모델 요청도 그림에 표시합니다.
- 클래스 그림은 현재 단원의 핵심 타입만 표시합니다. 아직 배우지 않은 Advisor·RAG·MCP는 넣지 않습니다.
- 코드가 보장하는 흐름과 모델이 선택할 수 있는 흐름을 명시합니다. Agent 그림의 도구 호출은 가능한 경로이지 매번 발생하는 보장이 아닙니다.
- 색상에 의미를 맡기지 않습니다. 노드·화살표의 한국어 설명만으로 구분할 수 있게 합니다.
- 보조 서버와 테스트 도구는 본문 실행 그림에서 생략하고, 테스트 절에서 외부 모델만 대체했음을 밝힙니다.
