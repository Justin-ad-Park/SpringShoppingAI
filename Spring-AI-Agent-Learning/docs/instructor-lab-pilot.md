## 05-3 수업 진행

05-3 교재의 질문 변경 실험에서 도구가 필요한 경우를 먼저 예상하게 합니다.<br>
수강생은 로컬 테스트를 실행하고, 두 번째 모델 요청의 도구 결과가 어디서 만들어졌는지 말합니다.<br>
첫 실습에서는 예측표와 중단점을 제공합니다. 해설 뒤에는 아래의 새 기록을 스스로 설명하게 합니다.

교재를 준비할 때는 ECC `code-explorer`의 방식으로 HTTP 진입점부터 모델·Java 사이의 전환을 추적합니다.<br>
`code-tour`의 위치 확인 방식을 사용해 각 중단점과 변수 이름을 실제 Java 파일에 맞춥니다.<br>
`pr-test-analyzer`의 방식으로 문제에서 요구하는 증거와 테스트의 검증문을 대조합니다. 12-7에서는 `rag-pipeline-reviewer`의 검색 결과와 모델 입력 분리도 적용합니다.

## 수강생에게 제공할 모의 기록

각 문제에서 ① 모델과 Java가 한 일, ② 금액 근거를 찾은 메시지와 값, ③ 값이 처음 달라진 위치를 적으세요.

### 사전 문제 — 커피 배송비

| 관찰 위치 | 기록 |
|---|---|
| 첫 모델 응답 | `calculateShipping("P02")` 요청, 호출 ID `shipping-coffee` |
| 두 번째 모델 요청 | `role=tool`, 호출 ID `shipping-coffee`, 상품가 28000원, 배송비 3000원, 총액 31000원 |
| 최종 응답 | “커피는 배송비 포함 28000원입니다.” |

### 사후 문제 — 텀블러 배송비

| 관찰 위치 | 기록 |
|---|---|
| 첫 모델 응답 | `calculateShipping("P03")` 요청, 호출 ID `shipping-tumbler` |
| 두 번째 모델 요청 | `role=tool`, 호출 ID `shipping-tumbler`, 상품가 35000원, 배송비 0원, 총액 35000원 |
| 최종 응답 | “텀블러는 배송비 포함 38000원입니다.” |

상품값과 정책은 [05단원의 카탈로그](../labs/05-00-tool-calling/src/main/java/com/example/ailearning/l05tools/domain/ProductCatalog.java)를 따릅니다. 답변 문장과 호출 ID는 평가를 위해 만든 모의 값입니다.

## 채점과 확대 기준

| 채점 항목 | 1점을 주는 답 |
|---|---|
| ① 실행 주체 | 모델이 도구와 상품 ID를 요청하고, Spring AI가 Java 도구 호출에 연결했다고 설명 |
| ② 근거 | 두 번째 모델 요청에서 같은 호출 ID의 도구 메시지를 지목하고 사전은 31000원, 사후는 35000원을 제시 |
| ③ 최초 불일치 | Java 결과를 받은 이후, 최종 답변에서 총액이 처음 달라졌다고 판단 |

ECC `eval-harness`의 방식으로 비교 전에 점수와 완료 기준을 정합니다.

1. 두 문항의 풀이 제한 시간은 각각 8분입니다. 사전 점수가 비슷한 사람끼리 짝을 짓고, 짝마다 기존 교재와 개편 교재에 한 사람씩 무작위로 배정합니다.<br>
   기존 교재는 개편 전 저장소의 같은 단원을 사용합니다. 두 그룹에 같은 학습 시간과 강사 힌트를 제공합니다.
2. 채점할 때는 사용한 교재를 가립니다. 배정한 전원을 기록하고, 미제출은 점수 0점과 소요 시간 8분으로 집계합니다.
3. 각 짝에서 개편 교재의 사전·사후 점수 상승폭이 기존 교재보다 얼마나 큰지 비교합니다.<br>
   ②와 ③ 모두에서 개선 방향이 보이고, 완료율과 소요 시간 중앙값이 악화되지 않을 때 다음 단원의 시범을 진행합니다. 작은 수업의 결과는 배정·완료 인원과 점수 변화를 함께 기록합니다.

## 후속 단원 배포용 문제

해당 단원의 기본 실습을 마친 뒤, 아래의 해당 문제만 수강생에게 제공합니다.

### 04 구조화 응답

`POST /api/criteria`에 “생활 카테고리에서 20000원 이하 상품을 찾아줘”를 보내고, 모델 응답으로 아래 JSON을 받았습니다.

```json
{"category":"음료","maxPrice":20000}
```

응답을 record로 받을 수 있는지, Java의 값 검증 결과와 HTTP 상태는 무엇인지, 질문과 처음 달라진 값은 무엇인지 설명하세요. 판단에 쓰는 코드 위치도 표시하세요. [04 실습](lessons/04-structured-output.md#4-실행하고-비교하기)

### 12-7 검색과 답변 평가

질문은 “상품 금액이 딱 30000원이면 무료배송인가요?”입니다. 기대 문서 ID는 `shipping`, 답변에서 찾는 문구는 `30000원`입니다.

| 관찰 위치 | 기록 A | 기록 B |
|---|---|---|
| 검색된 문서 ID | `shipping` | `return-opened` |
| 채팅 모델에 보낸 `user` 메시지의 정책 부분 | `[shipping] 기본 배송비는 3000원이며 상품 금액 30000원 이상은 무료배송입니다.` | 채팅 요청 기록 없음 |
| 모델 답변 | “30000원을 초과하면 무료배송입니다.” | 답변 없음 |

두 기록의 검색 검사와 문구 검사 결과를 예상하세요.<br>
기록 A에서 모델에 전달된 정책의 위치를 찾고, 답변이 [정책 원문](../labs/12-00-evaluation/src/main/resources/policies.md)에 맞는지 설명하세요. [12-7 실습](lessons/12-evaluation/07-retrieval-and-generation.md)
