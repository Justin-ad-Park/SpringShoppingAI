# 처음 배우는 개발자를 위한 학습 방법

이 교재는 Spring으로 Controller와 Service를 작성할 수 있지만, AI 모델은 처음 사용하는 개발자를 대상으로 합니다.
Spring Academy의 **배경 개념 → Spring AI 구현 → 실습** 구성을 참고하되, 한 수업의 입력·처리·결과를 더 작게 나눕니다.
공식 강의의 본문이나 코드를 번역한 자료가 아니라, 이 저장소의 쇼핑 예제를 설명하는 자체 교재입니다.

## 기획자와 함께 읽기

AI 기능을 기획하는 구성원은 [00장](lessons/00-llm-and-spring-ai.md)에서 모델과 Spring AI의 관계를 익힌 뒤, 04~13장 메인 문서의 **개념 먼저 이해하기** 부분을 순서대로 읽습니다. 새 용어·쇼핑 서비스 예시·각 기능의 역할을 코드 실행 없이 확인할 수 있습니다.

구현을 맡은 개발자는 이어지는 실습 안내와 소수업을 학습합니다. 기획자와 개발자는 같은 예시를 바탕으로 필요한 데이터, 모델이 판단할 부분, 코드로 검증할 조건을 함께 정할 수 있습니다.

## 한 번에 어디까지 읽을까요?

00~04는 각 교재의 절을 순서대로 읽습니다. 05~13은 각 단원의 목차에서 소수업으로 들어갑니다.
한 번에 전체 애플리케이션을 작성하는 과정이 아닙니다.

아래 표는 정상 동작을 처음 구현하는 수업의 권장 순서입니다. 모든 수업에서 모든 단계를 수행할 필요는 없습니다.
개념 수업은 문제·개념·예시와 확인 질문으로 이해를 점검할 수 있습니다. 실패·복구가 주제인 수업은 필요한 정상 동작을 복습한 뒤 실패 사례를 중심으로 학습합니다.
작은 변경 과제와 보충 읽기는 해당 수업의 목표를 확인하거나 설명을 더 이해하는 데 필요할 때 선택합니다.

| 단계 | 할 일 | 이번에 끝났다는 기준 |
|---|---|---|
| 개념 | 어떤 불편을 해결하는지 먼저 읽기 | 새 API 이름 없이 문제를 설명할 수 있음 |
| 코드 | 본문이 지정한 메서드 한두 개만 읽기 | 입력·호출 대상·반환값을 찾을 수 있음 |
| 실행 | 그대로 실행해 정상 결과 관찰 | 기대한 자료가 다음 단계에 전달됨을 확인 |
| 작은 변경 | 질문이나 옵션 하나만 바꾸기 | 변경 전후의 차이를 설명할 수 있음 |
| 보충 | 본문에서 분리한 상세 설명·동시성·테스트 보조 코드 읽기 | 현재 학습 목표에 필요한 부분을 찾아봄 |

## 코드에서 먼저 찾을 세 가지

예를 들어 첫 실습의 `ChatService.ask(message)`는 다음처럼 읽습니다.

```text
입력: Controller가 받은 질문 message
처리: user(message)로 현재 사용자 메시지를 넣고 모델에 요청
결과: content()가 반환한 답변 문자열
```

- `prompt()`는 요청 조립 시작입니다. 이 줄만 실행했다고 외부 모델을 호출한 것은 아닙니다.
- `user(message)`는 질문을 프롬프트에 넣습니다. 프롬프트는 역할을 가진 메시지들의 묶음입니다.
- `call().content()`는 이 동기 호출 흐름을 실행해 답변 텍스트를 받습니다.
- 다음 단원에서는 문자열 대신 record, 메시지 한 개 대신 이전 대화, 고정 문자열 대신 검색 근거를 추가합니다.

새 문법이 나오면 AI 개념과 구분하세요. `record`는 Java 데이터 묶음이고, `.entity(...)`는 모델 응답을 그 타입으로 변환하는 Spring AI 기능입니다.

## Java 문법과 AI 기능을 구분하기

| 코드 모양 | 먼저 이해할 의미 |
|---|---|
| `record` | 값들을 묶은 Java 데이터 타입. AI 전용 문법 아님 |
| `var result = ...` | 오른쪽 값으로 지역 변수의 타입을 추론. 어떤 객체가 반환되는지 먼저 확인 |
| `List.of(...)` | 여러 값을 순서 있는 목록으로 묶음 |
| `item -> ...` | 각 값에 적용할 동작을 전달하는 람다 표현식 |
| `stream().map(...)` | 목록의 각 값을 다른 값으로 바꾸는 Java 처리 |
| `filter(...)` | 조건을 만족하는 값만 남김. 모델이 판단하는 필터와 구분 |
| `.entity(SomeRecord.class)` | 모델 응답을 해당 Java 타입으로 변환하는 Spring AI 기능 |

코드의 모든 줄을 AI 기능이라고 생각하지 말고, 일반 Java 처리와 모델을 호출하는 부분을 표시해 보세요.

## 도메인 코드와 AI 연결 코드 구분하기

도메인은 서비스가 다루는 업무 영역을 뜻합니다. 04장 이후 실습에서 `domain` 패키지는 상품·검색 조건·가격 계산처럼 업무 자체를 표현하는 코드입니다. 먼저 이 기능의 입력과 결과를 이해한 뒤, 바깥의 Service와 도구 클래스에서 Spring AI에 연결하는 방법을 읽으세요.

| 위치 | 읽을 내용 | 예 |
|---|---|---|
| 각 단원의 `domain` | 업무 데이터와 규칙 | 검색 조건, 상품, 배송비 포함 가격 계산 |
| 기존 단원 패키지 | 모델 호출·도구 제공·HTTP 연결 | `CriteriaService`, `ShoppingTools`, Controller |

도메인 객체의 `UnitTest`도 `domain`에 있고, 모델 연결 테스트는 기존 단원 패키지에 있습니다. 대화 이력이나 모델 실행 결과를 보여주는 자료형은 해당 기능 옆에서 읽습니다.

## 무엇을 직접 작성해야 하나요?

| 코드 | 첫 학습에서 할 일 |
|---|---|
| Service의 프롬프트·도구 등록·검색 호출 | 직접 읽고 한 줄씩 설명 |
| Controller·입력 검증 | 익숙한 Spring 연결로 확인 |
| Spring AI 도구 호출 상한 | [05 보충 5](lessons/05-tool-calling/05-tool-call-limits.md)에서 설정과 제한 초과 응답 확인 |
| 모델 연결 타임아웃·재시도 | [02 보충 5](lessons/02-first-call/05-model-timeout-retry.md)에서 설정 변경과 실제 HTTP 요청 수 확인. 12장에서 실패 분석에 재활용 |
| `test-support`의 Mock 서버·결과 출력 | 공통 검증 도구. 단원에서는 지정한 응답·실제 결과·assertion부터 읽기 |
| 통합 단원의 여러 도구·메모리 조합 | 각 기능을 따로 실행한 뒤 책임 지도로 확인 |

보조 코드가 없는 것처럼 기능을 설명하지는 않습니다. 실행 제한은 별도 확장 모듈에서 학습하며, 격리 등 각 예제의 동작과 한계는 해당 수업에서 확인합니다.
처음부터 모든 클래스를 위에서 아래로 읽는 대신, 핵심 흐름을 이해한 뒤 호출되는 보조 코드로 확장합니다.

설정 이름과 루트 `.env` 작성 방법은 [실행 설정 안내](run-guide.md)에 모았습니다.

공통 도구의 API와 초기화 범위는 [test-support 안내](../test-support/README.md)에서 확인합니다.

## 테스트와 실제 모델 관찰은 다릅니다

Mock 테스트는 프롬프트 구성·도구 실행·값 검증 같은 Java 코드의 연결을 확인합니다.
고정 응답으로 통과했다고 모델이 한국어를 이해하거나 적절한 도구를 선택한다고 결론 내리지 않습니다.
실제 모델 실습에서는 답변·도구 선택·근거 사용을 따로 관찰합니다.

첫 실습은 단순한 두 클래스입니다. `FirstChatLocalModelTest`는 MockServer,
`FirstChatOpenAiLiveTest`는 실제 OpenAI에 접속합니다. IntelliJ에서는 원하는 클래스의 Run을 누릅니다.
첫 모듈의 전체 test에는 두 클래스가 포함됩니다. Mock만 원하면 클래스 필터를 사용합니다.
태그·실행 허용 변수·별도 Live 태스크를 도입하지 않습니다.

모든 학습 모듈의 실제 실행은 루트 `.env`를 읽습니다. 채팅은 `OPENAI_API_KEY`, `OPENAI_MODEL`을 사용하고,
임베딩을 사용하는 실습만 `OPENAI_EMBEDDING_MODEL`을 추가로 사용합니다.
09 검색 실습은 임베딩만 사용하므로 채팅 모델이 필요 없습니다.
두 업체를 사용하는 선택 실습은 Anthropic 설정도 필요합니다. 전체 대응은 [실행 설정 안내](run-guide.md)를 참고하세요.
`02-04-multiple-models`의 `MultipleProvidersLiveTest`는 기본 상태에서 실제 OpenAI를 호출합니다. Anthropic 호출 예제는 주석 처리되어 있으며, 해당 실습 안내에 따라 별도로 활성화합니다.
각 모듈의 전체 test에는 Live 클래스가 포함되므로, 로컬 테스트만 원하면 클래스 필터를 사용합니다.
`*LocalModelTest`는 `.env` 읽기를 끄고 고정 응답 HTTP 서버를 사용합니다. `*UnitTest`는 모델 연결 없이 Java 객체를 검증합니다. 실제 API를 호출하는 `*LiveTest`는 각 모듈에 별도로 있습니다.

## 단원마다 한 가지 바꾸기

먼저 해당 단원의 로컬 테스트를 통과시킨 뒤 아래 과제를 한 가지만 수행합니다.
코드·테스트를 바꾸는 과제는 변경 전후 결과를 비교하고 마지막에 원본으로 복원합니다.
로컬 명령은 [실행 안내](run-guide.md)의 클래스 필터를 사용하세요.
고정 응답은 프롬프트를 바꿔도 스스로 달라지지 않습니다. 프롬프트 과제는 전송 메시지를 검사하고, 실제 언어 이해는 별도 Live 실행에서 평가합니다.

| 단원 | 작은 과제 | 확인할 결과 |
|---|---|---|
| 00 개념 | “상품 가격 계산”과 “조건을 보고 다음 도구 선택”의 결정 주체를 각각 적기 | 계산은 Java, 다음 행동 선택은 모델이라고 설명할 수 있음 |
| 01 준비 | 실제 키를 출력하지 않고 로컬 테스트의 `.env` 읽기 해제 설정과 더미 키 위치 찾기 | 실제 API 연결 없이 첫 로컬 테스트 통과 |
| 02 첫 호출 | 첫 호출 테스트의 고정 응답 문구와 기대값을 같은 문구로 변경 | 응답 문구만 달라지고 HTTP 요청은 여전히 한 번 |
| 03 프롬프트 | system에 “두 문장 이내” 조건을 추가하고 전송 메시지 확인 | 조건이 system에 실렸는지 검사. 고정 답변 준수와 모델 이해를 혼동하지 않음 |
| 04 구조화 응답 | `SearchCriteria.validate()`에 가격 상한 100만원 제한을 추가하고 초과 값의 고정 응답 케이스 작성 | 객체 변환은 성공하되 업무 검증에서 HTTP 422 |
| 05 도구 호출 | `@Tool` 설명 한 문장을 바꾸고 모델에 보낸 `tools` 정의에서 확인 | 설명은 바뀌어도 Java 계산 결과는 같음 |
| 06 Workflow·Agent | 하이브리드가 배송비를 조회하지 않고 종료하는 고정 응답 케이스 추가 | 실제 조회가 없으므로 `NO_VERIFIED_OFFER` |
| 07 메모리 | `maxMessages(6)`을 4로 바꾸고 세 번 대화하기 | 저장 메시지는 최대 4개이며 이전 조건이 빠질 수 있음 |
| 08 Advisor | `TraceAdvisor` A·B의 order를 서로 바꾸기 | 도구 없는 요청의 진입·반환 순서가 역전됨. 내부 도구 루프는 별도로 관찰 |
| 09 검색 | 같은 고정 벡터에서 threshold 또는 topK 중 하나만 변경 | 결과 점수는 같고 포함되는 문서 수만 달라지는지 비교 |
| 10 RAG | 모델이 실제 검색에 없는 출처 ID를 선택하는 고정 응답 케이스 추가 | 답변 문구가 자연스러워도 `INVALID_CITATION` |
| 11 MCP | 상품 가격 상한이 1원인 하이브리드 검색을 고정 응답으로 재현 | 실제 MCP 검색이 비어 있으면 `NO_RESULTS`; 빈 장바구니 0원을 구매 성공으로 표시하지 않음 |
| 12 평가 | 평가용 고정 응답의 출처 ID 하나를 허위 ID로 변경 | 인용 검증 실패가 드러나며 자연스러운 문장만으로 통과하지 않음 |
| 13 통합 | `max-tool-calls`를 1로 줄여 여러 조회가 필요한 상담 실행 | `TOOL_LIMIT`이며 실패한 질문·답변은 메모리에 추가되지 않음 |

## 그림을 읽는 순서

[다이어그램 기준](diagram-guide.md)을 전체 수업에 적용합니다.
클래스 그림은 **책임**, 시퀀스 그림은 **한 요청의 시간 순서**, 흐름 그림은 **결정 주체**를 봅니다.
그림을 다 읽은 뒤 코드를 보는 것이 아니라, 그림의 호출 하나와 코드의 메서드 하나를 대응시키세요.
