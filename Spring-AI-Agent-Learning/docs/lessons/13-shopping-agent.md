# 13. 작은 쇼핑 상담 Agent — 배운 개념 연결하기

## 개념 먼저 이해하기

이제 각각 배운 기능을 **하나의 상담 경험으로 연결**합니다. 이처럼 여러 모델 호출·도구·대화 처리를 목적에 맞게 조율하는 것을 오케스트레이션(orchestration)이라고 부릅니다. 새로운 AI 모델이 생기는 것이 아니라, 모델과 기존 서비스가 맡을 일을 나누고 실행 흐름을 구성하는 것입니다.

예를 들어 “3만 원 이하 음료를 추천하고 반품 기간도 알려줘”라는 요청에는 상품 조건 해석, 가격·배송비 조회, 정책 검색, 결과 검증이 함께 필요합니다. 이어서 “예산을 4만 원으로 바꿔줘”라고 하면 이전 대화를 참고해 바뀐 조건으로 다시 처리해야 합니다.

| 기능 | 담당 역할 | 기획에서 정할 내용 |
|---|---|---|
| 의도 분류(intent classification) | 모델이 요청의 목적과 조건을 해석 | 상품 추천·정책 안내 중 무엇을 처리할지 |
| 도구 선택과 정보 조회 | 모델이 필요한 조회를 요청하고 서비스가 실행 | 업무별로 사용할 수 있는 도구와 실제 데이터의 출처 |
| 결과 검증 | 코드가 실제 조회 사실과 예산·출처 조건을 확인 | 어떤 결과를 사용자에게 제공할 수 있는지 |
| 대화 연결 | 애플리케이션이 이전 질문·답변을 다음 요청에 전달 | 유지할 조건과 성공·실패 때 저장할 내용 |

전체 흐름은 조건 해석 → 필요한 정보 조회 → 결과 검증 → 답변과 대화 저장으로 구성합니다. 그중 조회할 도구를 고르는 부분에 모델의 판단을 활용하므로, 고정 절차와 Agent를 결합한 혼합 방식입니다.

Spring AI는 모델 연결·도구 호출·대화 메시지 같은 구성 요소를 제공합니다. 어떤 작업을 묶을지, 결과를 어떤 기준으로 확정할지는 서비스 설계의 책임입니다. 이번 통합 실습의 범위는 상품 추천과 정책 안내이며, 주문 확정·결제 같은 변경 기능을 추가하려면 실행 도구와 사용자 확인 절차를 별도로 설계해야 합니다.

개념 참고: [Spring AI의 모델·도구를 결합한 처리 방식](https://docs.spring.io/spring-ai/reference/api/effective-agents.html).

## 실습 안내

상품 데이터·검색·가격 계산과 `Intent`의 상담 조건을 [domain 패키지](../../labs/13-00-shopping-agent/src/main/java/com/example/ailearning/l13shopping/domain)에 모았습니다. 모델 호출과 도구 연결 코드는 기존 단원 패키지에서 읽습니다.

먼저 04~12를 학습하고, 각 단원에서 배운 기능을 하나의 상담 흐름으로 연결합니다.
목표는 **상품 추천·정책 검색·후속 질문을 연결하면서 모델 판단과 Java의 책임을 설명하는 것**입니다.
명령은 모두 SpringShoppingAI 저장소 루트에서 실행합니다.
이 단원의 상품 도구는 애플리케이션 내부에서 실행합니다. 원격 도구를 사용하는 세 방식은 [11장 MCP](11-mcp-workflow-agent.md)에서 독립적으로 실행합니다.


## 세 단계로 실행하기

| 단계 | 먼저 확인할 것 | 읽을 코드·테스트 |
|---|---|---|
| 1. 한 번의 상담 | 조건 추출 → 도구 조회 → 실제 사실 검증 | `CounselWorkflow.execute()`와 동기 상담 테스트. 이전 대화는 빈 목록으로 전달 |
| 2. 후속 대화 | 변경하지 않은 예산·카테고리 유지와 저장 시점 | 13-4의 `CounselService`와 후속 질문 테스트 |
| 3. 실행 실패 | 횟수 상한·시간 초과 때 중단하고 저장하지 않음 | 13-4의 보충 설명과 상한·타임아웃 테스트 |

첫 단계는 아래 테스트 하나로 시작합니다. 고정 HTTP 응답을 사용하므로 실제 API 키가 필요하지 않습니다.

```bash
./gradlew :Spring-AI-Agent-Learning:labs:13-00-shopping-agent:test --tests 'com.example.ailearning.l13shopping.ShoppingAgentLocalModelTest.상담_흐름은_대화_저장이나_별도_실행기_없이_직접_호출할_수_있다'
```

이 테스트는 HTTP 상담 API나 별도 실행기 없이 Workflow를 직접 호출합니다. `RunState`는 호출 수·시간을 기록하고 제한하는 제공된 보조 객체로 사용합니다. 먼저 `draft`의 상품 총액·정책 출처와 실제 도구 호출 3회를 확인하고, 보조 객체의 내부 구현은 세 번째 단계에서 읽으세요. 실행 제한 기능은 처음부터 적용되어 있습니다.
