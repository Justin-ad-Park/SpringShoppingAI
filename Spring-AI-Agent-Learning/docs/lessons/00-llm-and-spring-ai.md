## 이번 수업의 목표

“질문을 입력하면 답변이 나온다”를 넘어, 요청이 어디로 이동하고 누가 답을 만드는지 설명합니다.
Spring AI를 설치하면 내 컴퓨터 안에 AI 모델이 생기는지, 기존 Java 서비스와 무엇이 다른지 구분합니다.
프롬프트·메시지·토큰·컨텍스트 등 모델 호출의 기본 용어를 이해하고, 간단한 예로 설명합니다.

## 익숙한 Spring 애플리케이션에서 시작하기

배송비를 계산하는 코드를 생각해 봅시다.

```java
int shippingFee(int amount) {
    return amount >= 30000 ? 0 : 3000;
}
```

입력이 20000이면 이 코드의 결과는 항상 3000입니다. 개발자가 규칙을 작성했기 때문입니다.
반면 “친구에게 줄 선물을 추천해줘”에는 정해진 답 한 개가 없습니다. 자연어 요청을 해석하고 문장을 만드는 일에 언어 모델을 사용할 수 있습니다.
무료배송 기준이나 실제 상품 가격처럼 정확한 사실과 계산은 이후에도 Java 코드와 데이터로 확인합니다.

## 모델과 LLM

- `모델(model)`은 학습으로 얻은 패턴을 이용해 입력에 대한 출력을 만드는 시스템입니다.
- `LLM(Large Language Model, 대규모 언어 모델)`은 텍스트를 이해하고 생성하는 데 쓰는 모델입니다.
질문에 답하거나, 문장을 요약하거나, 요청에서 상품 조건을 추출하도록 사용할 수 있습니다.

첫 실습에서는 제공 업체가 운영하는 모델을 HTTP API로 호출합니다. 모델 학습이나 설치는 하지 않습니다.
Spring AI는 해당 API를 Java/Spring 코드로 사용하도록 돕습니다.

## Spring AI의 위치

Spring AI는 **Spring Boot 애플리케이션 안에서 사용하는 Java 라이브러리**입니다.
`curl`은 터미널에서 HTTP 요청을 보내는 도구이고, 웹 클라이언트는 브라우저 등에서 요청을 보내는 프로그램입니다.
이들은 애플리케이션의 API를 호출합니다. Spring AI 코드는 요청을 받은 애플리케이션 내부에서 실행됩니다.

```text
[요청을 보내는 쪽]
curl 또는 웹 클라이언트가 HTTP 요청을 보냄
    ↓
[우리가 만드는 Spring Boot 애플리케이션]
Controller → Service → ChatClient → ChatModel 구현
                       └── Spring AI를 사용하는 부분 ──┘
    ↓ 제공 업체의 API로 HTTP 요청을 보냄
[제공 업체 서버]
외부 모델이 응답을 생성
```

생성된 응답은 애플리케이션을 거쳐 처음 요청한 curl 또는 웹 클라이언트에 전달됩니다.

`ChatClient`와 `ChatModel`은 이름이 비슷하지만 역할이 다릅니다.
지금은 **ChatClient는 호출을 편하게 구성하는 입구, ChatModel은 실제 모델 연결을 추상화한 인터페이스**라고 이해하세요.
구체적인 메서드는 03장에서 배웁니다.

Spring AI는 모델 자체가 아니고, 애플리케이션에서 모델을 호출하고 활용하도록 돕는 프레임워크입니다.
모델 연결, 메시지 구성, 도구 연결 등을 Spring 방식으로 작성할 수 있습니다.
다른 제공 업체로 바꾸더라도 기능 지원·모델 옵션·결과 품질까지 같아지는 것은 아닙니다.

## 반드시 알고 시작할 용어

| 용어 | 쉬운 설명 | 예 |
|---|---|---|
| 프롬프트(prompt) | 모델에 전달할 메시지를 순서대로 묶은 입력 | 응답 원칙을 담은 메시지 + 사용자 질문 메시지 |
| 메시지(message) | 역할과 내용을 가진 입력의 한 항목 | 역할: user, 내용: “선물 추천해줘” |
| 토큰(token) | 모델이 텍스트를 처리하는 단위 | 단어·단어 조각·기호 등. 글자 수와 일치하지 않음 |
| 컨텍스트(context) | 이번 호출에서 모델이 참고하는 정보 | 현재 질문, 함께 보낸 이전 대화나 문서 |
| 컨텍스트 창(context window) | 모델이 한 번의 호출에서 입력과 출력을 처리할 수 있는 최대 토큰 용량 | 이전 대화와 참고 문서가 길어지면, 답변에 필요한 공간을 고려해 일부 내용을 줄이거나 요약해야 함 |
| 환각(hallucination) | 사실과 다르거나 근거 없는 내용을 그럴듯하게 생성 | 존재하지 않는 상품 가격·반품 규정 |
| 모델 실행(inference, 추론) | 학습된 모델을 사용해 결과를 만드는 과정 | 애플리케이션이 API로 답변을 받는 작업 |

여기서 inference는 학습된 모델을 실행한다는 뜻입니다. 문제를 풀기 위해 단계적으로 판단하는 reasoning도 ‘추론’으로 번역되므로 문맥을 구분하세요.

### 프롬프트와 메시지의 관계

채팅 모델에 보내는 프롬프트는 하나 이상의 메시지를 순서대로 담습니다.
메시지는 역할과 내용을 가지며, Spring AI는 `system`(애플리케이션의 지시), `user`(사용자 입력),
`assistant`(모델 응답), `tool`(도구 실행 결과)을 구분합니다.
예를 들어 `system` 메시지 1개와 `user` 메시지 1개를 함께 보내면, 메시지 2개를 담은 프롬프트로 모델을 한 번 호출합니다.
이전 대화도 메시지로 포함할 수 있지만, 자동으로 저장되는 것은 아닙니다.

자세한 설명은 [프롬프트·메시지·역할 이해하기](00-llm-and-spring-ai/01-prompt-and-messages.md)에 있습니다.
**00장에서는 메시지의 관계와 네 가지 역할의 개요까지만 읽으면 충분합니다.**
ChatClient 코드 예제는 02장 이후, 도구 호출 예제는 05장을 배울 때 다시 읽으세요. 보충 문서 첫머리에 권장 학습 시점을 정리했습니다.

## 일반 API 호출과 어떤 점이 다른가?

- 실제 모델의 답변 문구는 같은 질문에도 달라질 수 있으므로, 고정 문장과의 일치만으로 성공을 판단하지 않습니다.
- 이후 로컬 Mock 테스트는 가짜 서버가 정해진 문장을 반환하므로 그 문자열이 그대로 전달되는지 비교합니다. 실제 모델의 자연어 품질을 평가하는 테스트와 목적이 다릅니다.
- 문법적으로 자연스러운 답변이 사실이라는 뜻은 아닙니다. 근거와 검증이 필요합니다.
- 모델은 이번에 전달된 정보로 응답합니다. 첫 실습은 이전 요청을 자동으로 기억하지 않습니다.
- 외부 API이므로 네트워크 지연, 인증 실패, 호출 제한이 있습니다. 입력·출력 토큰 등에 따라 비용이 발생할 수 있습니다.

예를 들어 “내 장바구니 배송비가 얼마야?”라고 물어도, 장바구니 정보를 보내거나 조회 도구를 제공하지 않으면 실제 배송비를 알 수 없습니다.
그럴듯한 숫자가 나왔다고 정상 동작으로 판단하면 안 됩니다.

## 앞으로 확장하는 방법

```text
문자열 응답
  → Java 객체로 조건 추출
  → Java 서비스를 도구로 제공
  → 코드 또는 모델이 도구 사용 흐름 결정
  → 이전 대화 제공
  → 문서 검색 결과 제공
  → 품질·비용·실패를 확인
```

여기서 **도구(tool)**는 상품 검색처럼 애플리케이션이 실행할 수 있는 기능입니다.
**Workflow**는 코드에 정의된 흐름을 따르고, **Agent**는 모델이 목표와 결과를 보고 다음 행동을 선택합니다.
지금 외울 필요는 없습니다. Java 서비스 호출을 배운 뒤 같은 도구로 두 방식을 비교합니다.

## 손으로 해보는 실험

아래 요청을 “모델의 문장 생성이 도움 되는 일”과 “정확한 데이터·코드가 필요한 일”로 나눠 보세요.

1. 고객에게 보낼 배송 지연 안내문을 부드럽게 작성한다.
2. 주문 금액 28,000원의 배송비를 계산한다.
3. 고객의 문장에서 선호 카테고리를 추출한다.
4. 지금 판매 가능한 상품 재고를 확인한다.

<details>
<summary>해설</summary>

1·3은 언어 모델을 사용할 수 있습니다. 3의 결과도 누락·허용 값 검증이 필요합니다.
2는 명시적인 배송 정책과 계산 코드, 4는 실제 재고 데이터 조회가 필요합니다.
하나의 서비스 안에서 두 종류를 함께 사용할 수 있습니다.
