## 이번 수업의 목표

“질문을 입력하면 답변이 나온다”를 넘어, 요청이 어디로 이동하고 누가 답을 만드는지 설명합니다.
Spring AI를 설치하면 내 컴퓨터 안에 AI 모델이 생기는지, 기존 Java 서비스와 무엇이 다른지 구분합니다.

## 익숙한 Spring 애플리케이션에서 시작하기

배송비를 계산하는 코드를 생각해 봅시다.

```java
int shippingFee(int amount) {
    return amount >= 30000 ? 0 : 3000;
}
```

입력이 20000이면 이 코드의 결과는 항상 3000입니다. 개발자가 규칙을 작성했기 때문입니다.
반면 “친구에게 줄 선물을 추천해줘”에는 정해진 답 한 개가 없습니다. 자연어 요청을 해석하고 문장을 만드는 일에 언어 모델을 사용할 수 있습니다.
무료배송 기준이나 실제 상품 가격처럼 정확한 사실과 계산은 이후에도 Java 코드와 데이터로 확인합니다.

## 모델과 LLM

**모델(model)**은 학습으로 얻은 패턴을 이용해 입력에 대한 출력을 만드는 시스템입니다.
**LLM(Large Language Model, 대규모 언어 모델)**은 텍스트를 이해하고 생성하는 데 쓰는 모델입니다.
질문에 답하거나, 문장을 요약하거나, 요청에서 상품 조건을 추출하도록 사용할 수 있습니다.

첫 실습에서는 제공 업체가 운영하는 모델을 HTTP API로 호출합니다. 모델 학습이나 설치는 하지 않습니다.
Spring AI는 해당 API를 Java/Spring 코드로 사용하도록 돕습니다.

## Spring AI의 위치

```text
curl 또는 웹 클라이언트
  → Controller: HTTP 요청을 받음
  → Service: 애플리케이션 작업을 수행
  → ChatClient: 모델 호출을 구성하는 Spring AI API
  → ChatModel 구현: 선택한 제공 업체의 요청 형식으로 연결
  → 외부 모델 API: 응답을 생성
  ← 응답이 같은 경로를 거쳐 클라이언트로 돌아옴
```

`ChatClient`와 `ChatModel`은 이름이 비슷하지만 역할이 다릅니다.
지금은 **ChatClient는 호출을 편하게 구성하는 입구, ChatModel은 실제 모델 연결을 추상화한 인터페이스**라고 이해하세요.
구체적인 메서드는 03장에서 배웁니다.

Spring AI는 모델 자체도, 정답 데이터베이스도 아닙니다.
모델 연결, 메시지 구성, 도구 연결 등을 Spring 방식으로 작성하도록 돕는 프레임워크입니다.
다른 제공 업체로 바꾸더라도 기능 지원·모델 옵션·결과 품질까지 같아지는 것은 아닙니다.

## 반드시 알고 시작할 용어

| 용어 | 쉬운 설명 | 예 |
|---|---|---|
| 프롬프트(prompt) | 모델에 전달할 메시지를 순서대로 묶은 입력 | 응답 원칙을 담은 메시지 + 사용자 질문 메시지 |
| 메시지(message) | 역할과 내용을 가진 입력의 한 항목 | 역할: user, 내용: “선물 추천해줘” |
| 토큰(token) | 모델이 텍스트를 처리하는 단위 | 단어·단어 조각·기호 등. 글자 수와 일치하지 않음 |
| 컨텍스트(context) | 이번 호출에서 모델이 참고하는 정보 | 현재 질문, 함께 보낸 이전 대화나 문서 |
| 컨텍스트 창 | 한 번에 처리할 수 있는 토큰 범위 | 무제한 대화를 그대로 넣을 수 없는 이유 |
| 환각(hallucination) | 사실과 다르거나 근거 없는 내용을 그럴듯하게 생성 | 존재하지 않는 상품 가격·반품 규정 |
| 추론/inference | 학습된 모델을 사용해 결과를 만드는 과정 | 애플리케이션이 API로 답변을 받는 작업 |

### 프롬프트 안에 메시지가 있다는 뜻일까?

네. **이 교재에서 다루는 채팅 모델의 프롬프트는 하나 이상의 메시지를 순서대로 담습니다.**
메시지는 그 안에 들어가는 개별 항목입니다. Spring AI의 `Prompt` 객체는 메시지 목록과 선택적인 모델 호출 옵션을 담습니다.
여기서는 먼저 메시지와의 관계에 집중하겠습니다.

일상적으로는 사용자가 입력한 질문 문장만 가리켜 “프롬프트”라고 부르기도 합니다.
하지만 애플리케이션에서는 사용자 질문 외에 응답 원칙이나 이전 대화도 모델에게 함께 보낼 수 있습니다.
따라서 이 교재에서는 **이번 호출에 보낼 메시지 묶음**이라는 뜻으로 사용합니다.

### 메시지는 역할과 내용을 가진다

메시지를 읽을 때는 두 가지를 확인합니다.

- **역할(role):** 어떤 종류의 메시지인가? 사용자 요청인지, 애플리케이션의 지시인지 등을 구분합니다.
- **내용(content):** 실제로 전달하는 질문이나 지시는 무엇인가?

예를 들어 “선물 추천해줘”라는 문자열을 사용자 메시지로 전달하면, 역할은 `user`, 내용은 “선물 추천해줘”입니다.
메시지 하나가 반드시 문장 하나인 것은 아닙니다. “선물 추천해줘. 예산은 3만원이야.”도 하나의 사용자 메시지에 담을 수 있습니다.

### 예시 1: 사용자 메시지 하나로 구성한 프롬프트

첫 실습에서는 다음 한 항목을 모델에게 보냅니다.

| 순서 | 메시지 역할 | 메시지 내용 |
|---|---|---|
| 1 | user — 사용자 요청 | Spring의 의존성 주입을 설명해줘. |

이 경우에는 **사용자 메시지 1개를 담은 프롬프트 1개로 모델을 호출**합니다.
“프롬프트에는 사용자 메시지 하나만 있다”는 말은 이 구성을 뜻합니다.

### 예시 2: 여러 메시지로 구성한 프롬프트

애플리케이션의 설명 원칙과 사용자 질문을 함께 보내려면 다음처럼 구성할 수 있습니다.

| 순서 | 메시지 역할 | 메시지 내용 |
|---|---|---|
| 1 | system — 애플리케이션의 지시 | Spring 입문자에게 쉬운 한국어로 설명하세요. |
| 2 | user — 사용자 요청 | Spring의 의존성 주입을 설명해줘. |

여기서는 **메시지 2개를 담은 프롬프트 1개로 모델을 호출**합니다.
메시지가 2개라고 모델을 2번 호출하는 것은 아닙니다. 모델은 함께 전달된 메시지를 참고해 응답을 생성합니다.
`system`과 `user`를 코드에서 설정하는 방법은 03장에서 실습합니다.

이후 이전 대화까지 포함할 때는 과거의 `user` 메시지와 모델 응답인 `assistant` 메시지도 함께 담을 수 있습니다.
이전 대화는 애플리케이션이 저장하고 다시 포함해야 합니다. 메시지 목록이 있다는 이유만으로 대화가 자동 저장되는 것은 아닙니다.

따라서 “프롬프트가 항상 문자열 하나인 것은 아니다”는 말은, **사용자가 입력한 문자열 하나만 전달하는 경우도 있지만 역할이 다른 여러 메시지를 묶어서 전달하는 경우도 있다**는 뜻입니다.

## 일반 API 호출과 어떤 점이 다른가?

- 답변 문구는 같은 질문에도 달라질 수 있습니다. 문장이 같아야 한다는 가정으로 테스트하지 않습니다.
- 문법적으로 자연스러운 답변이 사실이라는 뜻은 아닙니다. 근거와 검증이 필요합니다.
- 모델은 이번에 전달된 정보로 응답합니다. 첫 실습은 이전 요청을 자동으로 기억하지 않습니다.
- 외부 API이므로 네트워크 지연, 인증 실패, 호출 제한이 있습니다. 입력·출력 토큰 등에 따라 비용이 발생할 수 있습니다.

예를 들어 “내 장바구니 배송비가 얼마야?”라고 물어도, 장바구니 정보를 보내거나 조회 도구를 제공하지 않으면 실제 배송비를 알 수 없습니다.
그럴듯한 숫자가 나왔다고 정상 동작으로 판단하면 안 됩니다.

## 앞으로 확장하는 방법

```text
문자열 응답
  → Java 객체로 조건 추출
  → Java 서비스를 도구로 제공
  → 코드 또는 모델이 도구 사용 흐름 결정
  → 이전 대화 제공
  → 문서 검색 결과 제공
  → 품질·비용·실패를 확인
```

여기서 **도구(tool)**는 상품 검색처럼 애플리케이션이 실행할 수 있는 기능입니다.
**Workflow**는 코드에 정의된 흐름을 따르고, **Agent**는 모델이 목표와 결과를 보고 다음 행동을 선택합니다.
지금 외울 필요는 없습니다. Java 서비스 호출을 배운 뒤 같은 도구로 두 방식을 비교합니다.

## 손으로 해보는 실험

1. 고객에게 보낼 배송 지연 안내문을 부드럽게 작성한다.
2. 주문 금액 28,000원의 배송비를 계산한다.
3. 고객의 문장에서 선호 카테고리를 추출한다.
4. 지금 판매 가능한 상품 재고를 확인한다.
