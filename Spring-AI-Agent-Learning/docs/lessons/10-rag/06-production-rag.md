# 10-6. 상용 RAG의 자료 갱신과 품질 확인

## 이번 수업의 목표

10-1~5 이후의 선택 보충입니다. 적재·검색·생성 중 어떤 단계가 잘못됐는지 구분하고, 정책 변경을 검색 자료에 반영하는 기준을 설명합니다. 아래는 공개 자료를 참고한 쇼핑 서비스의 **설계 예시**이며 새 실행 모듈은 제공하지 않습니다.

## 1. “답변이 틀렸다”를 세 단계로 나누기

고객이 “개봉한 상품도 반품되나요?”라고 묻는데 미개봉 반품의 7일 규정으로 답했다고 가정합니다.

| 단계 | 확인할 자료 | 개선 방향 |
|---|---|---|
| 적재 | 개봉 반품 규정이 검색 자료에 있는가? | 원문 누락·오래된 버전·분할 위치 수정 |
| 검색 | 그 규정이 결과에 포함됐는가? | 질문 표현·필터·검색 개수·유사도 기준 비교 |
| 생성 | 맞는 원문을 줬는데 다른 조건으로 답했는가? | 지침·답변 형식·근거 대조 평가 개선 |

맞는 문서를 검색하지 못한 상태에서 프롬프트 문장만 바꾸거나, 검색은 맞는데 계속 청크 크기만 바꾸면 원인을 놓칠 수 있습니다. 검색된 ID·원문·버전과 최종 답변을 연결해 비교합니다. 원문 기록은 개인정보와 접근 권한을 고려해 필요한 범위로 제한합니다.

Spring Blog의 [Modular RAG 설명](https://spring.io/blog/2026/10/02/spring-ai-modular-rag-typesafe-jev/)은 주제가 비슷한 문서와 실제 답에 유용한 문서의 차이를 보여 줍니다. 이번 수업에서는 그 문제 구분을 참고하며, 해당 글의 재정렬 모델·외부 서비스는 설치하지 않습니다.

## 2. 정책이 바뀌면 무엇을 갱신할까?

다음은 예를 들어 미개봉 반품 기간이 변경됐을 때의 절차입니다. 실제 정책 변경을 의미하지 않습니다.

1. 원문 ID·버전·적용일을 정하고 최신 원문을 준비합니다.
2. Reader로 읽고 Splitter로 나눈 조각에 원문·버전을 연결합니다.
3. 기존과 같은 임베딩 모델로 새 조각을 적재합니다.
4. 같은 질문으로 새 정책이 검색되는지 확인합니다.
5. 적용 시점에 맞게 검색 대상을 전환하고 이전 조각을 제외·정리합니다.

추가만 반복하면 이전 정책과 새 정책이 함께 검색될 수 있습니다. 삭제 후 적재 중에는 자료가 비는 구간도 생길 수 있습니다. 상용 설계에서는 새 버전을 준비한 뒤 검색 대상을 전환할지, 갱신 중 조회를 어떻게 처리할지 정합니다. 사용하는 저장소의 삭제·갱신 계약도 확인해야 합니다.

현재 실습은 시작 시 작은 자료를 새로 적재합니다. 외부 저장소를 도입한다면 매 시작마다 전체 재적재하는 동작을 그대로 옮기기보다 적재 작업과 사용자 검색을 분리할지 검토합니다. [Spring AI ETL 설명](https://docs.spring.io/spring-ai/reference/api/etl-pipeline.html)은 읽기·변환·저장 API의 기준입니다.

## 3. 다음 단계로 넘어가기 전에 정할 기준

| 요구 | 설계할 내용 |
|---|---|
| 회원 등급·판매자별 정책 | 서버에서 확인한 권한에 맞는 문서만 검색·전달 |
| 적절한 근거 없음 | 답변 보류·추가 질문·상담원 연결 중 선택 |
| 인용 표시 | 검색한 출처 목록과 답변이 실제 인용한 출처를 구분 |
| 문서 안의 명령 문장 | 자료를 지침으로 취급하지 않도록 구성하고 공격 사례 평가 |
| 너무 많은 근거 | 검색 최대 개수뿐 아니라 실제 전달 길이·토큰 확인 |

예를 들어 “그 상품도 반품돼?”는 앞 대화의 상품 상태가 필요합니다. 대화 메모리는 질문 해석에, 정책 검색은 업무 근거에 사용합니다. 이전 답변을 최신 정책의 대체 근거로 쓰지 않습니다.

## 확인 질문

1. 올바른 개봉 반품 규정이 저장소에 없는데 유사도 하한만 낮추면 문제가 해결되나요?
2. 변경된 정책만 새로 추가하면 이전 정책의 검색도 자동 중단되나요?
3. 검색된 문서 목록을 표시하는 것과 답변의 모든 주장이 뒷받침되는 것은 같은가요?

<details>
<summary>해설</summary>

1. 아닙니다. 먼저 적재 누락을 해결해야 합니다. 하한을 낮추면 관련 없는 문서가 더 들어올 수 있습니다.
2. 아닙니다. 이전 자료 제외·삭제 또는 버전 필터 전환이 필요합니다. 구체적인 방법은 저장소와 적용 정책에 맞춥니다.
3. 다릅니다. 자료가 검색됐다는 사실 외에 각 주장이 그 자료의 조건과 일치하는지 확인해야 합니다.
