# 테스트 및 검증

## 단위 테스트와 빌드

```bash
./gradlew test bootJar
```

검증 범위:

- 범용 MCP 검색: 장바구니 무관성, 기본 상한 없음, 카테고리/재고/가격 경계/정렬/제외 조건.
- 실제 배송 견적: 수량 합계, 재고/배송그룹, 무료배송, 장바구니 불변성.
- 무료배송 업무: +7,000원 기본 정책, 사용자 예산 우선, 최신 합계의 범위 재계산, 부적격 후보 차단.
- 조건 병합: SET/CLEAR/KEEP, 새 업무 초기화, 카테고리 교체, 0원과 미지정 구분.
- 단기 상태: 사용자 격리, revision 충돌, 인프라 실패 시 보존, TTL/용량 제한, 동시 턴 직렬화.
- MCP 런타임: 응답 정규화, 업무 인자 미주입, 요청별 추적, 호출 한도.
- 일반 검색: 검증된 계획 실패 시 1회 직접 검색 전환.

## 브라우저 수동 확인

다음 순서로 같은 탭에서 질문합니다.

| 질문 | 기대 결과 |
|---|---|
| 무료배송을 채울 상품 추천해줘 | 기본 8,000~15,000원, 카드마다 배송비 0원 |
| 음료 카테고리에서만 추천해줘 | 이전 목적 유지, P004/P005 |
| 예산은 3만원까지 | 카테고리 유지, 명시 예산 적용 |
| 생활 카테고리에서만 추천해줘 | P009 추천 및 견적 |
| 예산 해제 | 생활 유지, 기본 15,000원 상한이라 결과 없음 |
| 카테고리 제한 해제 | 기본 무료배송 후보 복귀 |
| 적립금 조회 | 혜택 표시, 활성 검색 조건 유지 |
| 새로 3만원 이하 텀블러 찾아줘 | 일반 검색으로 새 업무, 배송 견적 없는 P009 |
| 새 검색 버튼 → 그래놀라 찾아줘 | 일반 검색에서 장바구니의 P001도 검색 가능 |

Mock은 위 예시 표현과 식품/음료/생활, 알려진 상품명에 한정한 규칙 해석입니다.
GPT는 `.env` API 키 설정 후 기본 모드로 별도 확인해야 합니다.

## 한계와 회귀 기준

실제 모델의 의도/조건 추출 정확성은 Stub 테스트로 증명되지 않습니다.
부정 표현(무료배송 상관없이), 새로운 검색과 이어지는 검색의 모호함, 예산 해제/전체 주문 예산,
지원하지 않는 카테고리, 이전 결과 지칭을 실제 모델 평가에 포함하세요.
조건 병합은 Java가 담당하지만 사용자의 문장에서 어떤 변경을 추출하는지는 GPT에 의존합니다.
모델이 확정 조건을 임의 변경해도 일반 검색 도구의 실제 MCP 인자는 서버의 검증된 query로 바인딩됩니다.

정상적인 결과 없음은 사용자 조건을 유지합니다. 네트워크 장애나 권한 오류를 NO_RESULTS로 위장하거나
워크플로우 무한 재시도로 처리하지 않습니다. 새 도메인 추가 시 같은 규약을 유지해야 합니다.

## 이번 리팩터링 검증 결과

- 전체 빌드와 단위 테스트 19개 통과.
- 실제 세 프로세스의 Mock 통합 테스트 통과.
- 로컬 OpenAI Stub을 통한 구조화 해석·도구 루프·계획 오류 fallback 통과.
- 브라우저에서 무료배송 추천 → 음료 카테고리 후속 요청 → 새 검색 버튼 → 일반 텀블러 검색 확인.
- 테스트용 프로세스만 종료했으며 기존 기본 포트의 사용자 서비스는 변경하지 않음.
- 실제 OpenAI GPT API를 호출한 품질 평가는 별도로 필요.
